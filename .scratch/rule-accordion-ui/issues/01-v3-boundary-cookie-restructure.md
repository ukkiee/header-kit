# 01 — v3 경계 + 마이그레이션 체인 + 응답 쿠키 재구조화

**What to build:** 저장 포맷이 v3로 오르고, 옛 상태를 켠 사용자가 **자기 응답 쿠키가 이전과 똑같이 나가는 것**을 확인할 수 있다. v1을 쓰다 오래 안 켠 사용자도 v2를 거친 사용자와 같은 곳에 도착한다. 새 버전으로 만든 내보내기 파일은 옛 버전이 삼켰다가 망가뜨리지 않는다.

응답 쿠키가 이름·값과 속성(Domain·Path·Max-Age·SameSite·Secure·HttpOnly)을 갖는다. 옛 원시 Set-Cookie 한 줄은 **엄격한 파서**로 읽어 모호함 없이 갈라질 때만 구조화하고, 아니면 **원시 그대로 보존**한다 — `Expires`의 쉼표, 값 안의 `=`, 모르는 속성은 전부 모호함으로 보아 추측하지 않는다. 잘못 파싱해 다른 쿠키를 내보내는 것이 원시로 남기는 것보다 나쁘다.

체인은 **v1→v2 도장 → 레거시 필터 실체화 → v2→v3 → 검증 → 커밋**이다. v1 변환은 버전 상수가 아니라 **리터럴 2**를 찍는다 — 상수를 찍으면 v1 데이터가 아무 변환 없이 v3로 라벨링된다. 레거시 필터 실체화가 v2→v3보다 **먼저**여야 하는 이유는 티켓 02가 벗길 대상이 그 실체화에서 태어나기 때문이다(이 티켓에서는 순서만 세우고 벗기기는 02가 한다).

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 포맷 번호가 v3이고, v3 파일을 옛 버전이 **변형하지 않고 거부**한다
- [ ] v1 변환이 리터럴 2를 찍고, 그 결과가 v2→v3를 한 번 더 지난 뒤 검증·커밋된다
- [ ] 레거시 필터 실체화가 v2→v3보다 먼저 돈다 (실체화는 필터 키가 없으면 즉시 반환하므로 검증 안에서 다시 불려도 무해하다)
- [ ] 응답 쿠키가 이름·값·Domain·Path·Max-Age·SameSite·Secure·HttpOnly를 갖고, 비운 속성은 조립된 쿠키에 붙지 않는다
- [ ] 옛 원시 값이 모호함 없이 갈라지면 구조화되고, 아니면 원시로 보존된다
- [ ] **두 경로 다 컴파일되어 나가는 헤더가 이전과 같다** — 이것이 이 티켓의 핵심 단언이다
- [ ] `Expires`의 쉼표·값 안의 `=`·모르는 속성·빈 값이 추측되지 않고 원시로 남는다
- [ ] 변환이 여러 번 돌아도 같은 결과다
- [ ] 옛 파일 가져오기도 같은 변환을 지난다
- [ ] 레거시 필터의 검증 케이스가 살아 있어 옛 파일의 부분 마이그레이션이 유지된다
- [ ] 마이그레이션 커밋이 쓰기 문을 지나 직렬화되고, 실패하면 다시 시도된다
- [ ] 권위 저장소에 **레거시 프로필 필터를 담은 진짜 v1**을 심은 픽스처로 위를 검증한다 (이미 실체화된 조건을 심으면 이 티켓이 세우는 순서를 통째로 비껴간다)
