# 02 — 퇴역(조건 4 + 메서드 3) + 일회성 공지 + 확인 명령

**What to build:** 제외 도메인·요청 출처 도메인·탭 도메인·자동 해제 시각으로 좁혀 둔 규칙과 HEAD·CONNECT·OTHER로 좁혀 둔 규칙을 가진 사용자가, 업그레이드 뒤 **그 조건이 없어졌다는 것과 몇 개가 영향받았는지를 알림으로 안다**. 넷 다 "여기엔 걸지 말라"를 말하던 것이라 사라지면 규칙이 조용히 넓어지는데, 그 이유를 모른 채 겪지 않게 하는 것이 이 티켓의 목적이다.

알림은 **보는 것으로 지워지지 않는다** — 확인을 눌러야, 그리고 그 확인이 쓰기 문을 지나 성공해야 사라진다. 팝업은 렌더 직후 닫히는 것이 정상 동작이라, 그리는 것만으로 소비하면 규칙이 이미 넓어진 뒤에 유일한 설명이 사라진다.

벗기기는 티켓 01이 세운 v2→v3 변환 안에서 일어난다. 새 쓰기 경로를 만들지 않는다.

**Blocked by:** 01 (v3 경계 + 마이그레이션 체인)

**Status:** ready-for-agent

- [ ] 퇴역 Condition 넷이 v2→v3에서 벗겨지고 세어진다
- [ ] HEAD·CONNECT·OTHER가 같은 변환에서 벗겨지고 세어진다
- [ ] 마지막 남은 메서드가 없어져 규칙이 모든 메서드에 걸리게 되면 그것도 영향 수에 세어진다
- [ ] **레거시 필터에서 실체화된** 퇴역 필드도 빠짐없이 벗겨진다 (01이 세운 순서 덕분에 가능해야 한다)
- [ ] 커밋된 v3를 다시 읽었을 때 퇴역 필드가 없다 — 저장소와 백업 파일에 남지 않는다
- [ ] 조건 정규화의 해당 분기가 같은 변경에서 사라진다 (남기면 낡은 값이 보이지 않게 살아남고, 벗기기 없이 지우면 무관한 저장 한 번에 조용히 사라진다)
- [ ] 영향 수가 공지로 상태에 담기고, 화면의 읽기는 **부수효과가 없다**
- [ ] 확인 명령이 쓰기 문을 지나 성공했을 때만 공지가 사라진다
- [ ] 보기만 하고 닫으면 다음에 다시 보인다
- [ ] 서비스 워커가 재시작해도 남는다
- [ ] 팝업과 탭을 둘 다 열어 뒀을 때 한쪽이 다른 쪽 몫까지 소비하지 않는다
- [ ] 확인 쓰기가 실패하면 공지가 그대로 남는다
- [ ] 공지가 **규칙이 넓어지기 전에** 이미 존재한다
- [ ] 가져오기 공지에 퇴역한 종류가 더해진다 (안 하면 기존 "레거시 필터를 규칙 조건으로 옮겼다" 공지가 거짓이 된다)
