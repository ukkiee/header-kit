# 06 — 규칙 폼 시안 정합 + 숨은 필드 + 수렴 저장

**What to build:** 폼이 시안 구성이 된다 — 이름·규칙 종류 / 적용 URL 패턴(**와일드카드·정규식 두 가지**) / 종류에 따라 나타나는 이름·값 / 응답 쿠키 속성 / 리소스 묶음 여덟 칩 · 요청 메서드 여섯 칩 / 저장 후 바로 활성화 · 취소 · 저장.

적용 방식(Override/Append), 빈 값의 뜻, 네 가지 매치 방식은 **화면에서 사라지되 스키마에는 남는다** — 숨은 필드다. 지우면 저장 상태가 통째로 기본값으로 교체되거나 저장된 패턴이 다르게 읽혀 규칙이 조용히 사라지기 때문이다. 옛 규칙은 그 값 그대로 계속 동작한다.

**수렴 저장**: 폼에서 저장하면 숨은 필드와 리소스 묶음이 **폼이 보여 준 값으로 다시 쓰인다**. 손대지 않은 규칙은 건드리지 않으므로, 넓히는 변경이 사용자가 스스로 저장한 규칙에만 붙는다. 원시로 보존된 응답 쿠키는 열면 그 값이 보이고, 저장해야 구조화된 형태로 확정된다.

규칙 초안 모듈이 여기서 선다 — 종류별 빈 초안, 종류를 바꿀 때 따라가는 값, 저장 직전 정리, 수렴 저장. 지금 이 규칙들은 500줄 넘는 폼 컴포넌트 안에 있고, 꺼내야 숨은 필드 3종 × 규칙 종류 8종의 조합을 단위로 덮을 수 있다.
