# 05 — 포매터가 들어오고, 포맷 커밋이 재현으로 증명된다

**What to build:** 코드 포맷이 사람마다 다르지 않게 되고, 다음 슬라이스부터 diff가 실제 변경만 담는다. 지금 포매터가 없어 기존 코드는 어떤 규범도 통과한 적이 없으므로 첫 실행은 사실상 전부 빨강이다 — 그래서 커밋을 둘로 나눈다.

**두 번째 커밋이 포맷만 바꿨다는 것을 재현으로 증명한다.** `git show --stat`은 증거가 되지 못한다. 경로와 줄 수만 보여 주므로 대량 포맷 커밋 안에 숨은 로직 수정이 그것을 그대로 만족시키고, 하필 그 증거는 리뷰어에게 **건너뛰라고** 말하는 데 쓰인다 — 틀린 증거 중에서도 가장 나쁜 자리다.

`oxfmt`는 아직 1.0 이전이라 버전을 **정확히 고정**한다. 마이너 사이에 출력이 달라지면 포맷 게이트가 비결정적이 된다. `sortTailwindcss`는 **끈 채로** 시작한다 — 켜면 클래스 순서가 전부 바뀌어 diff가 더 커지고, `cn()` 병합 순서에 의존하는 스타일이 있으면 시각적 회귀가 난다.

- [x] 커밋이 둘로 나뉜다: 설정·게이트·스크립트 등록이 하나, 전면 포맷 적용이 다른 하나
- [x] 포맷 커밋의 **부모**를 깨끗한 트리에 꺼내 커밋이 고정한 바로 그 버전의 `oxfmt`를 돌린 결과 트리가 포맷 커밋의 트리와 **정확히 같다**. 절차와 결과 트리 해시를 검증 문서에 적는다
- [x] **의미 있는 수정 한 줄을 그 커밋에 섞으면 이 증명이 실패하는 것**을 케이스로 확인한다. 실패하지 않으면 이 증명은 `git show --stat`과 같은 값을 가진다
- [x] `git show --stat`이 증거로 쓰이는 자리가 문서 어디에도 없다. 서술용으로 덧붙이는 것은 무방하다
- [x] 이미 포맷된 파일과 어긋난 파일 픽스처가 있고, 후자가 종료 코드 1을 낸다
- [x] `sortTailwindcss`가 꺼져 있고, 켜는 것이 별도 슬라이스라는 것이 표나 결정 기록에 적혀 있다
- [x] 포맷 전후로 **기존 스위트 전체와 실제 브라우저 검사**가 초록이다 — 동작을 바꾸지 않아야 하는 변경이므로 그것이 증거다
- [x] 이 티켓 뒤에 접근성 베이스라인을 뜬다는 순서가 06에 걸려 있다. 반대 순서면 첫 베이스라인이 이 커밋에서 통째로 어긋난다
