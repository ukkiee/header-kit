# 08 — CI가 빠른 게이트를 돈다

**What to build:** 게이트가 사람의 기억에 의존하지 않게 된다. 지금 `.github/`가 아예 없어 게이트 표를 세워도 그것을 지키는 주체는 언제나 로컬에서 돌리는 사람이고, **한 번 잊힌 게이트는 없는 게이트와 같다.**

브라우저가 필요 없는 게이트만 돈다. 실제 크롬을 띄우는 `smoke`·오버플로 게이트와 기기 기준선에 매인 성능 자문은 CI 밖에 둔다 — 앞의 둘은 느리고, 마지막은 러너 하드웨어가 바뀔 때마다 거짓 실패를 낸다.

**어느 게이트가 CI 대상인지는 워크플로가 아니라 레지스트리가 정한다.** 워크플로를 손으로 고쳐 레지스트리와 갈라서는 것을 러너가 막는다 — 01이 세운 네 자리 일치의 마지막 자리가 여기서 실제로 채워진다.

**Blocked by:** 03, 06, 07

**Status:** ready-for-agent

- [ ] GitHub Actions 워크플로 하나가 `ci: yes`인 게이트를 전부 돈다
- [ ] 워크플로가 도는 집합이 레지스트리의 `ci` 필드와 정확히 일치한다. 어긋나면 러너가 FAIL을 낸다 — 01에서 픽스처로만 확인하던 자리가 실제 워크플로로 채워진다
- [ ] `smoke`·오버플로 게이트·성능 자문이 `ci: no`이고, 그 이유가 표에 적혀 있다
- [ ] `bun run test`가 CI에서 돈다. `bun run test:browser`는 돌지 않는다 — 07이 세운 분류가 여기서 실제 효과를 낸다
- [ ] CI가 브라우저를 프로비저닝하지 않는다. 브라우저를 띄우는 테스트가 브라우저 없는 집합에 잘못 들어가면 07의 parity 검사가 먼저 잡는다
- [ ] 워크플로가 `needs: build`인 게이트를 돌리므로 빌드가 CI에서 한 번 돈다
- [ ] 워크플로 파일과 레지스트리가 어긋난 상태를 재현하는 픽스처가 있고 러너가 그것을 FAIL로 낸다
