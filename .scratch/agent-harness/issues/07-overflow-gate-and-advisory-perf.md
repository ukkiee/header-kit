# 07 — 오버플로는 게이트가 되고 성능 대조는 자문이 된다

**What to build:** 최대 길이 이름이 좁은 팝업의 레이아웃을 깨는 것이 매번 잡힌다. 지금 이 검사는 시작 성능 대조와 한 스크립트에 묶여 있어 **둘 다 등록되지 못했다** — 증명 강도가 다른 둘이 한 몸이라 어느 쪽 임계값도 정직하게 세울 수 없었다.

가로 오버플로 훑기는 같은 입력이면 어느 기기에서든 같은 답이라 **하드 게이트 자격**이 있다. 시작 성능 대조는 기준선 문서 스스로 기기를 기록하며 같은 기기에서만 유효하다고 적는다 — 하드 게이트로 걸면 다른 기기에서 거짓 실패를 내고, 그 거짓 실패를 고치는 유일한 길이 기준선을 느슨하게 하는 것이다. **게이트를 고쳐 통과시키는 것**, 정확히 금지된 일이다. 그래서 **자문 행**이 된다.

**준비 상태를 관측하지 않으면 이 게이트는 거꾸로 선다.** 아무것도 그려지지 않은 화면에는 넘치는 원소가 없어서 **빈 트리가 가장 잘 통과한다.** 지금 스크립트는 고정 시간을 기다리는데 앱은 비동기 상태 로딩 전까지 아무것도 렌더하지 않고 정렬 가능한 프로필 목록은 지연 import된다.

여기서 브라우저 테스트 분류도 함께 들어온다. **브라우저를 띄우는지는 import로 판정하지 않는다** — 이 저장소의 seam은 게이트를 자식 프로세스로 띄우라고 요구하므로, 규정을 지킨 테스트는 playwright를 import하지 않는다. import를 세면 그 테스트가 브라우저를 안 쓰는 것으로 보이고, 이름을 잘못 달면 브라우저 없는 CI가 크롬을 띄우려다 죽는다. 오탐이 아니라 **미탐**이고 하필 규정된 경로에서만 난다.

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] `ui-diag`가 둘로 갈라진다: 오버플로 게이트(hard)와 성능 대조(advisory). 둘 다 등록되고 표에 행이 선다
- [ ] 오버플로 게이트가 `needs: build`·`browser: yes`·`ci: no`로 등록된다
- [ ] 성능 대조가 `kind: advisory`이고, **기준선 기기 밖에서는 완료를 가로막지 않는다**는 것이 표에 적혀 있다
- [ ] 훑기 전에 **관측 가능한 준비 표지**를 요구한다: 심은 프로필이 전부 렌더됐다는 것(개수로 확인), 지연 로드되는 목록이 실제로 들어왔다는 것, 폰트가 적용됐다는 것
- [ ] 준비 표지가 제한 시간 안에 나타나지 않으면 그 자체가 **FAIL**이다. 기다림이 끝났다는 이유로 훑기로 넘어가지 않는다
- [ ] **시드가 실패해 화면이 빈 경우**와 **지연 로드가 끝나지 않은 경우**가 통과하지 못하고 FAIL을 내는 것을 케이스로 확인한다
- [ ] 넘치는 요소가 있는 시드와 없는 시드 픽스처가 각각 있다
- [ ] `bun run test:browser`가 생기고, 브라우저를 띄우는 테스트는 `*.browser.test.mjs`로 이름 짓는다. 두 명령의 glob이 그 규약에서 **서로 배타적으로** 파생된다
- [ ] 브라우저 판정이 레지스트리의 `browser` 필드에서 파생된다: **`browser: yes`인 게이트를 자식 프로세스로 띄우는 테스트 파일은 `*.browser.test.mjs`여야 한다**
- [ ] parity 픽스처 넷. 핵심은 **playwright를 직접 import하지 않으면서 브라우저 게이트를 띄우는, 이름이 잘못된 테스트**가 FAIL을 내는 것이다 — import를 세는 분류였다면 통과했을 자리이고, 이 저장소의 seam에서 실제로 나타나는 형태다. 나머지 셋: 직접 import하면서 이름이 틀린 파일도 FAIL, 브라우저 픽스처가 `test`에서 제외되는 것, 같은 픽스처가 `test:browser`에서 선택되는 것
