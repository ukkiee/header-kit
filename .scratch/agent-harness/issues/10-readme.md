# 10 — README

**What to build:** 처음 이 저장소를 여는 사람이 코드를 열기 전에 방향을 잡는다. 지금 README가 없어 무엇을 보는 중인지 알 방법이 없다.

이 문서의 주된 일은 **초록이 무엇을 뜻하는지 과장하지 않는 것**이다. 게이트가 무엇을 보장하는지만 적으면 읽는 사람은 나머지도 보장된다고 읽는다. 그래서 각 게이트에 대해 **무엇은 보장하지 않는지**를 함께 적는다 — 매니페스트 게이트는 권한 집합이 선언과 같다는 것을 증명하지 현재 권한 집합이 옳다는 것을 증명하지 않고, 접근성 지문은 새 진단이 없다는 것을 증명하지 키보드로 전체 흐름을 조작할 수 있다는 것을 증명하지 않는다.

## Comments

**닫음** — 수용 기준 7/7. 게이트 16행 전부 PASS · `gate:ci` 12행 PASS · 스위트 825 → 832.

산출물: `README.md` · `scripts/readme-parity.test.mjs`(픽스처 12).

**마지막 수용 기준을 검사로 읽었다.** "문서가 주장하는 명령과 게이트 이름이 실제 레지스트리와
일치한다"는 약속이 아니라 검사를 요구한다. README는 러너가 지키는 **네 자리 밖**이라 게이트가
하나 늘어도 러너가 보지 않는데, 이 문서의 주된 일이 "초록이 무엇을 뜻하는지 과장하지 않는 것"이라
낡은 README는 다른 낡은 문서보다 나쁘다 — **없는 보장을 있다고 말한다.**

재는 것은 산문이 아니라 집합과 이름이다: 한계 표의 게이트 집합 == 레지스트리(양방향) · 한계 칸이
비지 않았을 것 · `bun run <script>`가 실재할 것(코드 블록 안까지 — 사람이 복사하는 것이 거기 있다) ·
가리키는 경로가 실재할 것.

**주장을 코드로 대조했다.** 한계를 **틀리게** 적는 것은 안 적는 것보다 나쁘므로 16행을 스크립트에
맞춰 봤고, `manifest-gate` 행이 부정확했다 — "sandbox CSP를 재지 않는다"고 썼는데 실제로는 CSP
**키 집합**은 잠그고 `sandbox`의 **값**만 안 잰다.

**코드리뷰 2축이 잡은 것.**

- (Standards) **사실이 아닌 한계 하나.** `needs` 칸 구멍을 전면적인 것처럼 적었는데 `manifest-gate`는
  자기 행의 등록을 테스트로 못 박아 두어 예외다. 이 문서에서 가장 나쁜 종류의 틀림이고, 다음 사람이
  그 픽스처를 쓸모없다고 지우게 만든다.
- (Standards) **숫자와 목록을 옮겨 적었다.** `style만 4652건`(정본은 검증 문서)과 브라우저 게이트
  넷의 **이름·개수**. 후자는 바로 다음 문장이 "사람이 세는 것이 아니라 레지스트리의 `browser` 칸이
  정한다"고 스스로 반박하고 있었다. 둘 다 지웠다.
- (Standards) **`lint`를 과소 진술했다.** "correctness 카테고리만 켠다"는 레이어 방향이 강제되지
  않는다고 읽힌다. 카테고리 축의 한계만 말하고 무엇을 잡는지는 표로 넘겼다.
- (Standards) `a11y-gate` 행이 **개수 언어**였다("늘지 않았다"). 정본은 지문 **집합**이고, 그 말투는
  검증 문서가 정확히 거절하는 것이다. 실제 구멍 둘(고친 위반의 지문을 지우지 않으면 다시 들어와도
  통과 · `--update`가 넓히기도 한다)도 빠져 있어 함께 채웠다.
- (Spec) **한계 칸이 비어도 초록이었다.** 검사가 첫 칸만 읽어서 `| \`smoke\` | |`가 통과했다 —
  게이트 삭제는 잡고 **그 게이트의 한계 삭제**는 못 잡는, 이 문서의 주된 일이 뚫린 자리다.
- (Standards) **검사 자신에 픽스처가 없었다.** `readme`가 모듈 상수라 마커 가드가 한 번도 실행되지
  않았다 — 그것이 깨져도 이 파일은 늘 초록이다. `problems(text, ids, scripts)`로 인자화해 관계를
  하나씩 깨뜨리는 픽스처 아홉을 붙였다.
- (Spec) **"보장하지 않는 것"이 두 곳에 살았다.** 경계를 명시했다: README는 처음 온 사람을 위한
  한 줄 요약, 검증 문서가 임계값과 **근거**. 갈라서지 않게 하는 것은 id 집합뿐이고 산문은 검사하지
  않는다는 것도 함께 적었다.

**티켓 문면 하나를 따르지 않았다.** 수용 기준 6은 "`scripts/`가 타입 프로그램 밖이라 그곳에서는
**떠도는 프로미스가 잡히지 않는다**"를 적으라고 하는데, 그것은 **사실이 아니다** — 티켓 04가 실측으로
스펙 D13을 이미 정정했고(`oxlint --type-aware`는 `tsconfig`의 exclude와 무관하게 자기 타입 프로그램을
세운다), `.oxlintrc.json`의 `scripts/**` override는 `restrict-template-expressions` 하나만 끈다.
README에는 실제 한계(추론이 `any`로 떨어지는 자리)를 적었다. 티켓 문면이 스펙의 정정을 따라오지
못한 자리다.

**남은 위험.** 이 검사는 **산문을 재지 않는다** — 한계 칸에 틀린 내용을 적어도 비어 있지만 않으면
통과한다. 사실 여부는 사람이 본다(이번에 리뷰가 실제로 넷을 잡았다). 그리고 README가 손으로 적은
설명 중 레지스트리에서 파생되지 않는 것(브라우저 필요 여부의 서술 등)은 여전히 파리티 밖이다.
