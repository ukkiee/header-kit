# 09 — 하네스 코어가 AGENTS.md 안에 선다

**What to build:** 에이전트가 태스크를 시작할 때 이 저장소의 규율을 **이미 받은 상태**가 된다. 지금 `AGENTS.md`는 17줄짜리 설정 블록이고, **레이어 방향**은 지난 기능의 리뷰 산출물에, **Writer Lane** 불변식은 ADR에, 게이트 관행은 지난 검증 문서들에 흩어져 있다. 규칙이 지켜져 온 것은 규칙이 실려서가 아니라 매번 사람이 실어 날랐기 때문이다.

**하네스 코어**가 `<!-- core:begin -->` / `<!-- core:end -->` 사이에 인라인으로 선다(ADR 0018). `CLAUDE.md`는 지금처럼 `@AGENTS.md` 한 줄로 남는다. 별도 파일 + `@import`를 택하지 않는 이유는 그 형태가 "실제로 로드되었는가"를 증명 대상으로 만들기 때문이고, 그 증명의 비용에는 바닥이 없다.

**이 티켓이 마지막에서 두 번째인 이유:** 코어의 UI 규칙 줄은 임계값을 옮겨 적지 않고 **규칙의 존재와 그것을 강제하는 게이트의 이름**만 단다. 게이트가 없는데 그 이름을 먼저 적으면 가지고 있지 않은 검사를 선언하는 것이 되고, 그건 이 스펙이 세 라운드 내내 잡아낸 형태다. 이 시점에는 그 게이트들이 전부 실재한다.

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] 코어가 마커 사이에 인라인으로 서고, `CLAUDE.md`는 `@AGENTS.md` 한 줄 그대로다
- [ ] 코어가 담는 것: 권한 순서, 태스크 분류, 패키지 매니저 해석, **레이어 방향**, **게이트** 규율과 판정 넷, 완료 조건과 보고 형식, 코어 개정 규칙
- [ ] **Writer Lane**(ADR 0016)과 **Schema Version / Blocked** 판정이 코어에 들어간다 — 모르고 고치면 사용자 데이터가 사라지는데 게이트는 초록일 수 있는 것들이다
- [ ] 이미 게이트가 있는 규칙(i18n 하드코딩 금지, 번들 지연 계약, 접근성)은 **임계값을 옮겨 적지 않는다.** 규칙이 존재한다는 것과 그것을 강제하는 게이트의 이름만 한 줄씩 달고, 숫자와 목록은 게이트 한 곳에만 산다
- [ ] 코어가 자기 안에 목표 라인 수를 선언하고, `core-line-budget` 게이트가 **마커 사이 구간만** 재어 초과하면 FAIL한다
- [ ] 마커 쌍이 없거나 둘 이상이면 FAIL, 선언이 없거나 서로 다른 선언이 둘이면 FAIL — 어느 쪽이 지배하는지 모호한 상태를 통과시키지 않는다
- [ ] 픽스처 여섯: 예산 안, 예산 초과, 마커 없음, 마커 쌍 둘, 선언 없음, 서로 다른 선언 둘. 특히 **"마커가 없다"가 통과하면** 게이트가 아무것도 재지 않으면서 초록이 된다
- [ ] 게이트가 등록되고 표에 행이 선다. 코어의 게이트 절은 "표는 `docs/agents/verification.md`가 소유한다" 한 줄 포인터만 둔다
- [ ] 코어에 무엇이 살 자격이 있는지를 코어 자신이 말한다 — 태스크 종류와 무관하게 적용되거나, 없으면 틀린 일을 완료로 보고하게 만드는 것
- [ ] 예산을 넘겼을 때 하는 일이 예산을 올리는 것이 아니라 옮기는 것이라는 점과 옮기는 순서가 코어에 적혀 있다
- [ ] 코어 본문은 한국어, 섹션 제목·게이트 슬러그·보고 형식 제목은 영어다
- [ ] `AGENTS.md`에 H1이 둘이 되므로, 마크다운 린트를 쓴다면 **그 파일에만 범위를 좁힌** 예외를 둔다. 저장소 전체로 규칙을 끄지 않는다
