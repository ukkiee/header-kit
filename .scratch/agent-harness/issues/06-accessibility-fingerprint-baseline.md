# 06 — 접근성 진단이 위치에 무관한 지문으로 고정된다

**What to build:** 접근성 상태가 나빠지는 것이 잡힌다. 지금 UI 파일 49개와 스토리 25개, Base UI + shadcn을 쓰면서 접근성 검사가 0이라 `div`에 `onClick`을 다는 종류의 결함을 잡을 것이 없다.

기존 위반을 이번에 전부 고치지는 않는다. 그러나 베이스라인을 **총 개수**로 잡으면 하나를 고치고 다른 하나를 새로 만드는 변경이 총계를 그대로 둔 채 통과한다 — 지키려던 것을 정확히 놓친다. 그래서 베이스라인은 **진단 지문의 집합**이다.

**지문에 줄·열을 넣지 않는다.** 넣으면 전면 포맷 적용이 모든 지문을 한꺼번에 무효화하고, 게이트가 포맷 전용 커밋을 거짓으로 막는다. 그것을 푸는 손쉬운 길인 베이스라인 재취득이 하필 **진짜 교체 회귀를 함께 축복한다** — 이 설계가 막으러 온 그것이다. 위반 앞에 빈 줄 하나를 넣는 평범한 편집도 같은 일을 한다.

이 게이트가 **주지 않는 것**도 함께 적는다. 지문 베이스라인은 "새 진단이 없다"까지만 준다. 키보드만으로 전체 흐름을 조작할 수 있다거나 모든 컨트롤에 접근명이 있다는 **관측된 보장**은 주지 않는다.

- [x] 베이스라인을 **포맷 적용 뒤에** 뜬다
- [x] 지문이 `규칙 이름 + 파일 + 진단 대상의 정규화된 식별자`이고 **줄·열을 담지 않는다**. 같은 파일 안에 구분 불가능한 진단이 여럿이면 개수까지가 지문의 일부다

- [x] **위반 앞의 줄만 바뀌어 위치가 밀린 경우는 통과한다.** 줄·열을 지문에 넣었다면 실패했을 자리다. 앞의 조건과 반대 방향이라 한쪽 픽스처만으로는 다른 쪽을 잡지 못한다
- [x] 이 게이트가 주지 않는 것(관측된 키보드 조작·접근명 보장)이 표의 임계값 칸이나 인접 서술에 적혀 있다
- [x] 테스트가 게이트를 자식 프로세스로 띄우고 종료 코드와 상태 줄만 단언한다
