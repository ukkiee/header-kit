# agent-harness — 항상 로드되는 하네스 코어, 소유자 있는 게이트 표, 그리고 비어 있던 검사들

**Triage:** ready-for-agent

**Source:** `../web-app-agent-template` (2026-08-11 읽음) — 그 저장소의 하네스 설계를 이 스택에 맞게 옮긴다. 복사가 아니라 재작성이다.
**Base:** `main` @ `fffb9d6` · **Branch:** `feat/agent-harness`

## Problem Statement

이 저장소의 규율은 실재한다. 그런데 **로드되지 않는 자리**에 있다.

`src/`의 일곱 층은 `core → runtime → platform → ui → features → app → entrypoints` 순서로 단방향 하향 규칙을 지킨다. 실측하면 프로덕션 코드의 위반은 0이다 — `core`는 교차 import가 하나도 없는 순수 leaf이고, `ui`는 위를 향해 아무것도 부르지 않는다. 그런데 이 규칙이 적힌 곳은 **지난 기능의 리뷰 산출물**(`docs/reviews/arch-restructure/design.md`)이고, `AGENTS.md`는 트래커·라벨·도메인 문서를 가리키는 17줄짜리 설정 블록이다. 그래서 새 세션의 에이전트는 레이어 방향이 존재한다는 사실 자체를 모른 채 작업을 시작한다. 규칙이 지켜져 온 것은 규칙이 실려서가 아니라 매번 사람이 실어 날랐기 때문이고, 실어 나르는 것을 한 번 잊으면 그날의 위반은 아무 데도 걸리지 않는다.

강제도 없다. 레이어 방향을 어긴 import를 잡는 검사가 하나도 없다. 실제로 위반이 이미 하나 있다 — 통합 테스트 하나가 `runtime`에서 `platform`을 향해 위로 부른다. 아무도 몰랐던 것이 아니라 **알 방법이 없었다**.

검사 자체가 비어 있는 영역도 있다. 린터가 없고 포매터가 없다. UI 파일 49개와 스토리 25개, Base UI + shadcn을 쓰면서 접근성 검사가 0이다. `div`에 `onClick`을 다는 종류의 결함을 잡을 것이 없고, 순환 import를 잡을 것도 없다. CI가 없어서 게이트를 돌리는 주체는 언제나 사람이다.

게이트 표에 소유자가 없다. 실행 가능한 검사가 일곱 개 돌고 있지만(`check`·`test`·`build`·`smoke`·`bundle-gate`·`writer-lane-gate`·`storybook:build`) **무엇이 게이트인지, 임계값이 얼마인지, `N/A`가 무슨 뜻인지 한자리에서 말하는 문서가 없다**. 판정은 매번 그때의 `verification.md`가 새로 만든다. 결과로 두 가지가 새고 있다: 게이트 스크립트 다섯 중 둘(`audit-smoke-barriers`·`ui-diag`)이 `package.json`에 등록되지 않아 사실상 아무도 돌리지 않고, `tsconfig.json`이 `scripts/`를 exclude해 **게이트를 수행하는 스크립트 자체가 어떤 검사도 받지 않는다** — 334KB짜리 `smoke.mjs`를 포함해 다섯 개 전부, 테스트도 0이다.

`ui-diag`에는 성격이 다른 두 검사가 한 스크립트에 묶여 있어 둘 다 등록되지 못했다. 가로 오버플로 훑기는 같은 입력이면 어느 기기에서든 같은 답을 내는 결정론적 검사인데, 기기에 매인 시작 성능 대조와 한 몸이라 함께 묶여 있다.

마지막으로 이 저장소에는 README가 없다. 처음 보는 사람이 무엇을 보는 중인지 알 방법이 없다.

## Solution

에이전트가 **모든 태스크에서 반드시 받는** 지시 묶음(하네스 코어)을 `AGENTS.md` 안에 인라인으로 세운다. 흩어져 있던 것 — 레이어 방향, Writer Lane 불변식, 게이트 규율, 완료 조건 — 이 한자리에서 항상 실린다. 코어의 크기는 코어가 스스로 선언한 라인 예산을 게이트가 재는 것으로 지킨다.

게이트 표에 소유자를 준다. 사람이 읽는 표는 `docs/agents/verification.md`가, 기계가 읽는 같은 목록은 `scripts/gates.txt`가 들고, `scripts/run-gates.mjs`가 전부 돌린다. 러너는 돌리는 것에 더해 **네 자리가 서로 어긋나지 않았는지** 검사한다 — 표, `gates.txt`, `package.json` 스크립트, CI 워크플로. 하나라도 갈라서면 FAIL이다.

비어 있던 검사를 채운다. `oxlint`가 린트·접근성·레이어 방향·순환 import를 한 번에 보고, `oxfmt`가 포맷을 본다. MV3 매니페스트 불변식을 재는 게이트를 새로 쓰고, `ui-diag`에서 결정론적인 오버플로 검사를 떼어 진짜 게이트 행으로 올린다. 기기에 매인 성능 대조는 자문 행으로 남긴다. 빠른 게이트는 CI가 돌린다.

그리고 README를 쓴다.

## Implementation Decisions

### D1 — 코어는 `AGENTS.md`에 인라인으로 살고, import하지 않는다

`<!-- core:begin -->` / `<!-- core:end -->` 마커 사이에 코어가 직접 들어간다. `CLAUDE.md`는 지금처럼 `@AGENTS.md` 한 줄로 남는다. ADR 0018이 이 결정과 근거를 담는다.

**버린 대안 — 별도 파일 + `@import`.** import는 "실제로 로드되었는가"를 증명 대상으로 만드는데, 인라인된 코어로 답한 세션과 파일을 조용히 읽어 답한 세션은 답만 봐서는 구별되지 않는다. 원본 하네스가 이 길을 갔다가 자기 structure 게이트에 세 번 거절당했고 — 매번 다른 이유였고 매번 고침이 옳았는데 더 미묘한 채널이 남았다 — 결국 "불투명한 로더에 대해 부정을 증명하는 비용에는 바닥이 없다"로 결론짓고 인라인으로 옮겼다. 부수적으로 `@import`는 Claude Code 전용이라 다른 AGENTS.md 소비자는 코어를 받지 못한다.

### D2 — 코어의 크기는 코어가 선언하고 게이트가 잰다

코어는 자기 안에 목표 라인 수를 선언하고, 게이트는 **마커 사이 구간만** 재어 초과하면 FAIL한다. 마커 쌍이 없거나 둘 이상이면, 선언이 없거나 서로 다른 선언이 둘이면 FAIL이다 — 어느 쪽이 지배하는지 모호한 상태를 통과시키지 않는다.

임계값을 넘겼을 때 하는 일은 예산을 올리는 것이 아니라 옮기는 것이고, 옮기는 순서를 코어가 정한다. 초기 예산은 작성 후 실측해 정한다.

### D3 — 무엇이 코어에 사는가: 판정이지 목록이 아니다

들어오는 것은 두 가지다. 태스크 종류와 무관하게 적용되는 것, 또는 **없으면 틀린 일을 완료로 보고하게 만드는** 것.

- 항상 적용: 권한 순서, 태스크 분류, 패키지 매니저 해석, 레이어 방향, 게이트 규율과 판정 넷, 완료 조건과 보고 형식, 코어 개정 규칙.
- 둘째 조건 통과: **Writer Lane**(ADR 0016)과 **Schema Version / Blocked 판정**. 모르고 고치면 사용자 데이터가 사라지는데 게이트는 초록일 수 있다.
- **이미 게이트가 있는 것은 임계값을 옮겨 적지 않는다.** i18n 하드코딩 금지와 번들 지연 계약은 코어에 한 줄씩 — 규칙이 존재한다는 것과 그것을 강제하는 게이트의 이름만 — 으로 들어간다. 숫자와 목록은 게이트 한 곳에만 산다. 규칙은 그것을 담을 수 있는 가장 왼쪽 층에 인코딩하고 산문은 마지막 수단이라는 원칙이 여기서도 적용된다.

**버린 대안 — 공통 규율만 담고 확장 고유 불변식은 ADR 포인터로.** 짧지만, 에이전트가 ADR을 열지 않으면 Writer Lane을 모른 채 저장소를 고친다.

### D4 — 게이트 표는 사람용과 기계용을 나눠 갖되 러너가 일치를 강제한다

- `docs/agents/verification.md` — 사람이 읽는 표.
- `scripts/gates.txt` — 기계가 읽는 **레지스트리**. 이것이 "무엇이 게이트인가"의 정의다.
- `scripts/run-gates.mjs` — 등록된 게이트를 돌리고 행별 판정을 **진짜 출력에서** 만든다.
- 코어의 게이트 절은 "표는 `docs/agents/verification.md`가 소유한다" 한 줄 포인터만 둔다.

**레지스트리의 한 행이 드는 필드**(플랜 게이트 r1 F1이 요구한 스키마):

| 필드 | 뜻 |
| --- | --- |
| `id` | 게이트 식별자. 표의 행과 이 값으로 맞춘다 |
| `script` | `package.json`의 스크립트 키 |
| `kind` | `hard`(완료를 막는다) 또는 `advisory`(관측만 남긴다) |
| `ci` | CI 워크플로가 이 게이트를 도는가 |
| `needs` | 선행 조건. 지금 쓰이는 값은 `build` 하나다(D4a) |
| `browser` | 이 게이트가 실제 브라우저를 띄우는가. 테스트 분류가 이 값에서 파생된다(D12) |
| `na` | 이 행이 `N/A`가 될 수 있는 유일한 조건. 없으면 `never` |

**참여하는 스크립트의 범위를 레지스트리가 정한다.** `package.json`에는 `dev`·`zip`·`test:watch`·`storybook`·`postinstall`처럼 게이트가 아닌 스크립트가 이미 있고 앞으로 더 생긴다. 이것들은 **검사에 참여하지 않는다** — "모든 package 스크립트가 표에 있어야 한다"는 규칙은 영구히 빨강이라 검사가 아니라 소음이다.

러너가 검사하는 **네 자리 일치**는 따라서 등록된 게이트에 대해서만 성립한다: 레지스트리 행에 대응하는 표의 행이 없거나, `package.json`에 그 스크립트 키가 없거나, `ci: yes`인데 워크플로에 없거나, 반대로 워크플로가 등록되지 않은 게이트를 돌리면 FAIL.

**역방향의 경계를 여기서 밝힌다.** 등록되지 않은 게이트(고아 게이트)를 잡는 검사는 `scripts/` 안에서 **선언된 이름 규약**(`*-gate.mjs`)을 따르는 파일에만 미친다. 그 규약 밖의 이름으로 새 게이트 스크립트를 만들고 레지스트리에 넣지 않으면 **이 검사는 그것을 잡지 못한다**. 이름 휴리스틱을 넓혀 닫을 수 있는 종류의 구멍이 아니므로 — 넓힐수록 평범한 스크립트를 오탐한다 — 닫는 대신 여기 적는다. 규약 밖 이름을 쓸 이유가 생기면 그때 레지스트리에 넣는 것이 규약이다.

**버린 대안 — 코어 안에 표를 직접.** 표는 게이트가 늘 때마다 바뀌는데 코어는 가장 안 바뀌어야 할 문서이고, 12행 넘는 표가 라인 예산을 먹는다. 기계가 읽을 데이터가 따로 없으면 러너가 마크다운을 파싱해야 한다.

**버린 대안 — 글롭으로 게이트 발견.** 글롭은 "존재하는 게이트"를 "존재해야 할 게이트"의 정의로 만든다. 선언된 게이트가 사라져도 아무 일도 일어나지 않는다.

### D4a — 산출물을 읽는 게이트는 순서를 가지며, 낡은 산출물 위에서 돌 수 없다

게이트 다섯이 빌드 산출물(`.output/chrome-mv3`)을 읽는다: 기존 `bundle-gate`·`writer-lane-gate`·`smoke`, 새 `manifest-gate`·`overflow-gate`. 러너가 순서 없이 "전부 돌리면" 이들은 **직전 빌드의 산출물**을 읽을 수 있고, 그러면 지금 소스에서 늘어난 권한이 낡은 매니페스트에 대해 초록으로 통과한다. 검사하지 않으면서 초록을 내는 것 — 이 기능이 없애러 온 바로 그 형태다.

**러너의 실행 순서를 DAG로 고정한다.**

1. `needs: build`인 게이트가 하나라도 돌 예정이면, 러너가 먼저 **이 회차만의 산출물 디렉터리**를 만들고 프로덕션 빌드를 **한 번** 돌린다.
2. 빌드가 성공하면 그 디렉터리에 대해서만 소비자 게이트가 돈다. 러너는 그 경로를 소비자에게 **명시적으로 넘긴다.**
3. 빌드가 실패하면 소비자 게이트는 `BLOCKED`이다 — `FAIL`도 `N/A`도 아니다. 실패한 것은 그 게이트가 아니고, 돌 조건이 없었던 것도 아니다. `BLOCKED`은 완료를 막는다.
4. 빌드는 한 번만 돈다. 게이트마다 빌드를 다시 도는 것은 시간뿐 아니라 **어느 산출물을 재는지**를 흐린다.

**러너가 만들지 않은 산출물 위에서는 소비자 게이트가 돌지 않는다.** 소비자를 직접 부르는 것(예: `bun run bundle-gate`)은 여전히 가능하되, 러너를 통해 돌 때는 이 회차의 빌드가 만든 산출물임이 러너에게 보장된 상태여야 한다. 산출물이 없는데 소비자가 불리면 그 게이트는 `FAIL`이고, 사유는 "이 회차의 빌드 산출물이 없다"이다 — **`N/A`가 아니다.** 대상이 없는 것과 대상을 만들지 못한 것은 다르다.

**순서만으로는 부족하다 — 겹친 실행도 막아야 한다.** 위 1–4는 **한 번의 호출 안에서만** 성립한다. 러너 둘이 겹치면(사람과 CI, 또는 에이전트 둘) A가 빌드한 산출물을 B가 지우고 다시 만들고, 그 사이에 A의 소비자가 절반만 쓰인 디렉터리나 B의 산출물을 잰다. 산출물 경로는 하나뿐이라 순서 규칙이 이것을 잡지 못한다 — D4a가 막으러 온 실패가 다른 문으로 그대로 들어온다.

**해결은 잠금이 아니라 경로 분리다.** 처음 답은 지우기–빌드–소비 구간 전체를 잠그고 죽은 잠금을 회수하는 것이었다. 그것이 틀린 이유는 **"소유자가 죽었다"가 "쓰는 것이 다 멈췄다"를 뜻하지 않기 때문**이다 — 러너가 죽어도 그 빌드 자식 프로세스는 살아남아 디렉터리에 계속 쓸 수 있고, 그러면 다음 러너가 잠금을 회수해 지우고 다시 빌드하는 동안 두 쓰기가 겹친다. 잠금이 막으려던 것이 회수 경로로 그대로 돌아온다. 그것을 닫으려면 프로세스 그룹 소유권과 "모든 후손이 멈췄다"는 판정이 필요한데, 그건 또 하나의 **부정 증명**이고 비용에 바닥이 없다.

그래서 잠금을 강화하는 대신 **잠글 것을 없앤다.** 러너는 회차마다 고유한 산출물 디렉터리에 빌드하고 그 경로를 소비자에게 넘긴다. 두 러너가 겹쳐도 서로 다른 경로에 쓰므로 섞일 트리가 없고, 죽은 프로세스가 남길 잠금도 없다. 살아남은 자식이 계속 쓰더라도 그것이 쓰는 곳은 **자기 회차의 디렉터리**이지 다음 회차의 것이 아니다.

**대가는 소비자가 경로를 인자로 받아야 한다는 것이다.** 지금 다섯 소비자는 `.output/chrome-mv3`를 하드코딩한다. 이것을 인자로 바꾸는 것이 이 결정에 딸린 작업이고, 부수적으로 **테스트하기 쉬워지는** 방향이다 — 픽스처 트리를 가리킬 수 있게 되므로 원장의 산출물 픽스처들이 실제 빌드 없이 성립한다. 인자 없이 직접 부르면 기존 기본 경로를 쓴다.

### D5 — `tsc`를 대체하지 않고 `oxlint`를 더한다

`check`는 `tsc --noEmit` 그대로 두고, `lint`가 `oxlint`로 새 행이 된다.

**버린 대안 — `oxlint --type-check`로 대체.** 대체는 "oxlint가 tsc가 잡는 것을 빠짐없이 잡는다"를 전제하는데 그것은 측정되지 않았다. 이 저장소는 `noUncheckedIndexedAccess`·`noImplicitOverride`·`verbatimModuleSyntax`를 켜고 있고 tsgolint가 셋을 같은 강도로 존중하는지 확인되지 않았다. 틀렸을 때 생기는 것은 정확히 이 기능이 없애려는 것 — 검사하지 않는 초록 게이트다. 병행은 그 주장을 공짜로 측정하게 만들고, 같다는 근거가 쌓이면 그때 별도 슬라이스로 합친다.

### D6 — 레이어 방향은 `oxlint` overrides가 강제한다

레이어별 `overrides`에 `no-restricted-imports`로 금지 그룹을 적고, `import/no-cycle`을 함께 켠다. 도구가 늘지 않는다 — 린트·접근성·레이어·순환을 한 실행이 본다.

**버린 대안 — `dependency-cruiser`.** TypeScript 7에서 **0개 모듈을 검사하고 종료 코드 0을 낸다.** TS 7 패키지가 고전 컴파일러 API를 싣지 않아서다. `@swc/core`를 함께 깔면 동작하지만, 그 의존이 사라지는 순간 게이트는 빨간색이 아니라 초록으로 죽는다. 이 기능이 막으러 온 실패 양식 그 자체다.

**버린 대안 — 자체 `scripts/layer-gate.mjs`.** 순서를 배열 한 줄로 표현할 수 있어 설정이 갈라설 자리가 없지만, 도구가 하나 늘고 동적 `import()`를 보려면 파서가 필요해진다.

**이 선택이 안고 가는 위험과 그 대응은 Testing Decisions가 닫는다** — 21쌍 중 한 줄이 빠져도 설정은 조용히 통과하므로, 그것을 잡는 것은 설정이 아니라 테스트다.

**참고로 확인된 사실:** `oxlint`에는 `import/no-restricted-paths` 규칙이 **없다**(import 플러그인 33규칙 전수 확인). 레이어 표현은 `no-restricted-imports` + `overrides` 조합으로만 가능하다.

### D7 — 레이어 규칙에 테스트 예외를 두지 않고, 위반한 테스트를 옮긴다

현재 유일한 위반은 통합 테스트 하나가 `runtime`에서 `platform`을 위로 부르는 것이다. `*.test.ts`를 게이트 범위 밖으로 빼지 않는다 — 그러면 테스트가 레이어를 뚫는 것을 영구히 허용하게 된다. 대신 그 테스트를 **두 층을 모두 부를 수 있는 자리**, 즉 컴포지션 루트가 사는 `entrypoints`로 옮긴다. 이 테스트가 재는 것이 실제로 배경 컴포지션 루트의 동작이므로 자리가 뜻과 맞는다.

**버린 대안 — 문서상 레이어 순서를 고쳐 `platform`을 `runtime` 아래로.** 그러면 이 import가 합법이 되지만, 지난 기능이 세운 설계 결정을 테스트 하나 때문에 개정하는 것이 된다.

### D8 — 포매터 도입은 설정 커밋과 포맷 커밋을 분리한다

`oxfmt`를 도입하되 커밋을 둘로 나눈다: 설정·게이트·스크립트 등록이 한 커밋, 전면 포맷 적용이 다른 커밋. 다음 슬라이스부터 diff가 깨끗해진다.

**두 번째 커밋이 포맷만 바꿨다는 것은 재현으로 증명한다.** `git show --stat`은 증거가 되지 못한다 — 경로와 줄 수만 보여 주지 내용도 의미도 보여 주지 않으므로, 대량 포맷 커밋 안에 숨은 로직 수정이 그 증거를 그대로 만족시킨다. 그리고 이 증거는 리뷰어에게 **건너뛰라고** 말하는 데 쓰이므로, 틀린 증거 중에서도 가장 나쁜 자리에 있다.

대신 이렇게 잰다: 포맷 커밋의 **부모**를 깨끗한 트리에 꺼내고, 커밋이 고정한 바로 그 버전의 `oxfmt`를 돌린 뒤, 그 결과 트리가 포맷 커밋의 트리와 **정확히 같은지** 본다. 같으면 그 커밋은 포매터가 만든 것 이상을 담지 않았다는 뜻이고, 다르면 무엇이 더 들어갔는지가 diff로 나온다. 이 절차 자체를 검증 문서에 기록하고, 결과 트리 해시를 함께 적는다.

`sortTailwindcss`는 **끈 채로** 시작한다. 켜면 클래스 순서가 전부 바뀌어 포맷 diff가 더 커지고, `cn()` 병합 순서에 의존하는 스타일이 있으면 시각적 회귀가 난다. 이 저장소는 시각 계약을 실제 브라우저 검사로 재고 있으므로, 켜는 것은 그 게이트들이 초록임을 확인한 뒤 별도 슬라이스로.

`oxfmt`는 아직 1.0 이전이다. 버전을 **정확히 고정**한다 — 마이너 사이에 출력이 달라지면 포맷 게이트가 비결정적이 된다.

### D9 — `ui-diag`를 증명 강도로 가른다

한 스크립트 안에 성격이 다른 두 검사가 있다.

- **가로 오버플로 훑기** — 경계 프로필을 심고 고정 크기에서 모든 엘리먼트의 가로 넘침을 본다. 같은 입력이면 어느 기기에서든 같은 답이다. **하드 게이트 행**으로 올린다.

  **다만 준비 상태를 관측하지 않으면 이 게이트는 거꾸로 선다.** 아무것도 그려지지 않은 화면에는 넘치는 원소가 없어서 **빈 트리가 가장 잘 통과한다.** 지금 스크립트는 고정 시간을 기다리는데, 앱은 비동기 상태 로딩이 끝나기 전까지 아무것도 렌더하지 않고 정렬 가능한 프로필 목록은 지연 import된다. 느린 실행에서는 빈 화면 또는 절반만 그려진 화면을 훑고 "넘침 없음"을 보고한다.

  그래서 훑기 전에 **관측 가능한 준비 표지**를 요구한다: 심은 프로필이 **전부** 렌더됐다는 것(개수로 확인), 지연 로드되는 목록이 실제로 들어왔다는 것, 폰트가 적용됐다는 것. 준비 표지가 제한 시간 안에 나타나지 않으면 그것 자체가 `FAIL`이다 — 기다림이 끝났다는 이유로 훑기로 넘어가지 않는다. 그리고 **시드가 실패한 경우가 통과할 수 없음**을 증명하는 케이스를 테스트에 둔다.
- **시작 성능 대조** — 기준선 문서 스스로 기기를 기록하며 같은 기기에서만 유효하다고 적는다. 하드 게이트로 걸면 다른 기기에서 거짓 실패를 내고, 그 거짓 실패를 고치는 유일한 길이 기준선을 느슨하게 하는 것 — 게이트를 고쳐 통과시키는 것이다. **자문 행**으로 남긴다.

자문 행은 게이트 표에 있고 관측을 남기지만 완료를 가로막지 않는다. 표가 그 사실을 명시한다.

### D10 — MV3 매니페스트 게이트는 빌드 산출물의 불변식을 잰다

빌드된 매니페스트를 읽어 확인한다: manifest version이 3인가, 권한 집합이 의도한 그대로인가(현재 `declarativeNetRequest`·`storage` 둘과 호스트 권한), **최소 크롬 버전이 선언된 하한과 정확히 같은가**, 프로덕션 CSP에 `unsafe-eval`이 없는가.

최소 크롬 버전을 "선언돼 있는가"로 재면 아무것도 재지 않는 것과 같다 — `"80"`이 통과하고, 그러면 dNR 세션 규칙과 응답 헤더 수정이 없는 브라우저에 설치가 허용된다. 이 저장소가 108을 요구하는 이유는 `wxt.config.ts`에 이미 적혀 있으므로, 게이트는 그 숫자와의 **정확한 일치**를 잰다. 권한을 정확한 일치로 재기로 해 놓고 버전만 존재 검사로 두면 같은 게이트 안에서 강도가 어긋난다.

권한 집합은 **정확한 일치**로 잰다. 부분집합으로 재면 권한이 늘어나는 것을 놓치는데, 이 게이트의 존재 이유가 정확히 그것이다. `wxt.config.ts`는 이미 어떤 권한을 왜 뺐는지 주석으로 적고 있다 — 이 게이트가 그 주석을 검사로 만든다.

**버린 대안 — Mozilla `addons-linter`.** 실측 결과 Chrome 전용 확장에 Firefox 요구사항 3건을 오류로 낸다. 그 셋을 억제하고 쓸 수는 있으나, 억제 목록 자체가 유지 대상이 되고 이 게이트가 재려는 것과 겹치지 않는다.

**확인된 사실:** WXT 0.20에는 `lint`/`validate` 명령이 없고, WebExtension용 eslint 플러그인은 npm에 존재하지 않는다. 자체 스크립트 말고 길이 없다.

### D11 — 미등록 게이트 둘을 등록한다

`audit-smoke-barriers`를 `package.json`에 등록한다. 이 스크립트의 헤더는 **자신이 등록되지 않는 것이 의도**라고 적고 있으므로 이는 문서화된 결정의 개정이다. 헤더가 든 근거는 "인자로 다른 리비전의 사본을 검사할 수 있다"인데, 등록은 그 능력을 없애지 않는다 — 인자는 여전히 넘길 수 있다. 반면 미등록의 비용은 실재한다: 이 감사는 smoke의 단언이 한 테스트씩 밀리는 결함을 막는 것인데, 사람이 기억해야 돌아가면 기억하지 않은 날 무방비해진다. 헤더의 해당 문단을 고치고 변경 이유를 `decisions.md`에 남긴다.

`ui-diag`는 D9대로 갈라 등록한다.

### D12 — CI는 빠른 게이트만 돌린다

GitHub Actions 워크플로 하나가 브라우저 없이 도는 게이트를 전부 돌린다. 실제 크롬을 띄우는 `smoke`·`overflow-gate`와 기기 기준선에 매인 성능 자문은 CI 밖에 둔다 — 앞의 둘은 느리고, 마지막은 러너 하드웨어가 바뀔 때마다 거짓 실패를 낸다.

CI가 도는 게이트 집합은 레지스트리의 `ci` 필드가 선언하고 러너가 일치를 검사한다(D4). CI를 손으로 고쳐 레지스트리와 갈라서는 것을 막는다.

**테스트 명령을 둘로 가른다.** 스펙 초안은 `scripts/**/*.test.mjs` 전부를 `bun run test` 하나에 넣으면서 동시에 CI를 브라우저 없이 돌리려 했는데, 오버플로 게이트의 테스트는 본질적으로 실제 브라우저를 띄우므로 두 요구가 충돌한다. 그래서:

**두 집합을 파일명 규약이 정한다.** 브라우저를 띄우는 테스트는 `*.browser.test.mjs`로 이름 짓고, 두 명령의 glob이 그 규약에서 **서로 배타적으로** 파생된다.

- `bun run test` — `src/**/*.test.ts?(x)` + `scripts/**/*.test.mjs` 중 `*.browser.test.mjs`를 **뺀** 것. **CI가 돌린다.**
- `bun run test:browser` — `**/*.browser.test.mjs`만. 로컬에서 돈다.

규약을 정하지 않으면 "브라우저 없는 집합"이라는 말에 출처가 없고, 그 집합에 대한 parity 단언은 자기 자신을 근거로 삼는 순환이 된다. 두 glob이 한 규약에서 파생되므로 **어느 테스트 파일도 두 집합 모두에, 또는 어느 집합에도 속하지 않을 수 없다.**

**브라우저를 띄우는지는 import로 판정하지 않는다 — 레지스트리가 판정한다.** import를 보는 분류는 **이 스펙이 강제하는 형태를 정확히 놓친다.** 게이트 테스트는 대상을 자식 프로세스로 띄우라고 요구받으므로(테스트 결정의 seam), 오버플로 게이트의 테스트는 `vitest`와 `child_process`만 import하고 playwright는 **띄워진 게이트가** import한다. import를 세면 그 테스트는 브라우저를 안 쓰는 것으로 보이고, 이름을 잘못 달면 브라우저 없는 집합에 들어가 CI가 크롬을 띄우려다 죽는다. 오탐이 아니라 **미탐**이고, 하필 규정된 경로에서만 난다.

그래서 판정은 레지스트리의 `browser` 필드에서 파생된다: **`browser: yes`인 게이트를 자식 프로세스로 띄우는 테스트 파일은 `*.browser.test.mjs`여야 한다.** 레지스트리는 이미 "무엇이 게이트인가"의 SSOT이므로 분류가 별도 진실 원천을 만들지 않는다.

**parity 테스트가 검사하는 것**은 그 규칙이다. 여기에 더해 브라우저 픽스처 하나가 `test`에서 **제외되고** `test:browser`에서 **선택되는** 것을 단언해 두 glob이 실제로 배타적임을 본다. 이것이 없으면 새 브라우저 테스트가 무심코 브라우저 없는 집합에 들어가 CI에서 알 수 없는 이유로 죽는다.

seam은 여전히 하나다(테스트 결정 참조). 갈라지는 것은 seam이 아니라 **어느 명령이 어느 집합을 도는가**뿐이다.

### D13 — 게이트 스크립트를 타입 검사 밖에 두는 상태는 이번에 닫지 않는다

`tsconfig.json`이 `scripts/`를 exclude하는 것은 그대로 둔다. 대신 `oxlint`의 검사 범위에 `scripts/`를 포함해 **타입 없이 잡히는 것만** 잡고, 게이트 스크립트의 **동작**은 테스트가 본다(Testing Decisions). 첫 실행에서 기존 위반이 다량 나올 수 있으므로 그것을 베이스라인으로 기록한다 — 베이스라인은 늘어날 수 없고, 줄이는 것은 별도 작업이다.

**"타입 없이 잡히는 것"의 경계를 정확히 적는다.** 미사용 변수·미사용 import·닿을 수 없는 코드·오타성 전역 참조는 타입 정보 없이 잡힌다. **떠도는 프로미스는 잡히지 않는다** — `typescript/no-floating-promises`는 타입 인식 린팅을 요구하고 `.mjs`는 타입 프로그램 밖이다. 스펙 초안이 이것을 반대로 적었다. 떠도는 프로미스 검출은 type-aware가 실제로 도는 `src/`의 이야기이며(스토리 15가 약속하는 것도 그쪽이다), `src/`에 **실패해야 하는 픽스처**를 두어 그 규칙이 정말 켜져 있는지 증명한다. 규칙이 목록에 있다는 것과 규칙이 도는 것은 다르다.

### D13a — 접근성은 개수가 아니라 지문으로 베이스라인을 잡는다

기존 접근성 위반을 이번에 전부 고치지는 않는다. 그러나 **총 개수**를 베이스라인으로 삼으면 하나를 고치고 다른 하나를 새로 만드는 변경이 총계를 그대로 둔 채 통과한다 — 지키려던 것을 정확히 놓치는 베이스라인이다.

그래서 베이스라인은 **진단 지문의 집합**이다. 새 지문이 하나라도 나타나면 FAIL이고, 기존 지문이 사라지는 것은 언제나 허용된다(베이스라인에서 지운다). 개수가 같아도 구성이 바뀌면 잡힌다.

**지문에 줄·열을 넣지 않는다 — 위치에 안정적이어야 한다.** 지문이 `규칙 + 파일 + 줄:열`이면 전면 포맷 적용이 **모든 지문을 한꺼번에 무효화**한다. 위반은 그대로인데 옛 지문이 사라지고 새 지문이 생긴 것으로 읽혀서, 게이트가 포맷 전용 커밋을 거짓으로 막는다. 그리고 그것을 푸는 유일한 손쉬운 길이 베이스라인 재취득인데, **그 재취득이 진짜 교체 회귀를 함께 축복한다** — 이 설계가 막으러 온 바로 그것이다. 위반 앞에 빈 줄 하나를 넣는 평범한 편집도 같은 일을 한다.

지문은 `규칙 이름 + 파일 + 진단 대상의 정규화된 식별자`로 잡는다. 식별자는 그 진단이 가리키는 것을 위치에 의존하지 않고 지목하는 값이다(예: 문제가 된 요소·속성의 이름, 또는 명시적으로 부여한 억제 ID). 같은 파일 안에 구분 불가능한 진단이 여럿이면 개수까지를 지문의 일부로 삼는다.

**베이스라인 취득 시점은 전면 포맷 적용 뒤다.** 순서가 반대이면 첫 베이스라인이 포맷 커밋에서 통째로 어긋난다. 이 순서는 D8의 커밋 구성과 함께 지켜져야 하며, 티켓 순서가 이를 반영한다.

**이 게이트가 주지 않는 것도 적는다.** 지문 베이스라인은 "새 진단이 없다"를 준다. 키보드만으로 전체 흐름을 조작할 수 있다거나 모든 컨트롤에 접근명이 있다는 **관측된 보장**은 주지 않는다 — 그것은 실제 브라우저에서 초점 순서와 접근명을 읽어야 나오는 것이고 이 스펙의 범위 밖이다. 스토리 13·14는 이 게이트가 실제로 주는 것에 맞춰 좁혀 썼다.

### D14 — README를 쓴다

무엇을 보고 있는지, 어떤 게이트가 무엇을 보장하고 **무엇은 보장하지 않는지**, 어떻게 돌리는지를 담는다. 초록이 무엇을 뜻하는지 과장하지 않는 것이 이 문서의 주된 일이다.

## Testing Decisions

### 좋은 테스트가 단언하는 것

**외부 동작만이다.** 게이트에게 그것은 **종료 코드**와 **출력한 상태 줄** 둘이다. 내부 헬퍼 함수, 출력 서식, 트리를 훑는 순서는 단언하지 않는다. 게이트를 고쳐 쓰는 일이 테스트를 깨뜨리면 안 되고, 게이트가 잘못된 답을 내는 일은 반드시 테스트를 깨뜨려야 한다.

**관계를 깨뜨리는 픽스처가 없는 단언은 검사가 아니라 주장이다.** 각 관계마다 그 관계를 어긴 입력을 만들어 FAIL을 확인한다. 통과 케이스만 있는 테스트는 vacuous pass를 잡지 못한다 — 이 저장소는 이미 그 실패를 한 번 겪었고 그 기록이 `i18n-coverage` 테스트의 주석에 남아 있다(평면 스캔이 features를 놓쳐 통과하던 자리).

### seam — 하나다

**vitest가 검사 대상을 자식 프로세스로 띄우고, 종료 코드와 출력만 단언한다.**

게이트 스크립트에는 이것이 가장 높은 seam이다. 스크립트들은 export가 없는 실행 파일이라 프로세스가 실제 호출 방식 그 자체이고, 안으로 손을 뻗을 길이 없다는 것이 이 seam의 값이다.

레이어 규칙도 같은 seam으로 들어온다. `oxlint` 자체를 픽스처 트리 위에서 자식 프로세스로 띄운다.

**새 seam은 추가하지 않는다.** `vitest.config.ts`의 include를 `scripts/**/*.test.mjs`까지 넓히는 것이 전부다.

**명령은 둘로 갈린다(D12).** `bun run test`가 브라우저를 띄우지 않는 전부를, `bun run test:browser`가 브라우저를 띄우는 게이트 테스트를 돈다. seam이 갈라진 것이 아니라 같은 seam을 도는 명령이 둘인 것이다 — 어느 쪽이든 검사 대상은 자식 프로세스이고 단언하는 것은 종료 코드와 출력이다. 분류가 맞는지는 parity 테스트가 검사한다.

### 각 관계가 빚진 픽스처

**코어 라인 예산** — 예산 안, 예산 초과, 마커 없음, 마커 쌍 둘, 선언 없음, 서로 다른 선언 둘. 뒤 넷은 전부 FAIL이어야 하고, 특히 "마커가 없다"가 통과하면 게이트가 아무것도 재지 않으면서 초록이 된다.

**레이어 방향** — 일곱 층 각각에 다른 여섯 층을 전부 import하는 파일을 둔 픽스처 트리 하나. `oxlint`를 **한 번** 돌려 상향 쌍 21개가 전부 보고되고 하향 쌍은 하나도 보고되지 않는 것을 단언한다. `overrides`에서 한 줄이 빠지면 그 쌍이 출력에 나타나지 않아 즉시 빨강이다 — 이것이 D6의 위험을 닫는 장치다. 설정 파일을 읽어 21쌍을 세는 방식은 **채택하지 않는다**: 그것은 표가 완전한지만 보고 표가 실제로 거절하는지는 보지 못한다.

> 이 픽스처가 성립하려면 `oxlint`의 `overrides.files` 패턴이 설정 파일 위치가 아니라 실행 cwd 기준으로 풀려야 한다. 첫 티켓에서 이것을 먼저 실측하고, 아니면 설정을 픽스처 트리에 복사해 넣는 형태로 바꾼다. **가정하지 않고 잰다.**

**순환 import** — 순환을 만든 픽스처가 FAIL을 내는 것.

**러너의 네 자리 일치** — 어긋남 각각에 픽스처 하나씩: 레지스트리에만 있음, 표에만 있음, `package.json` 스크립트 없음, `ci: yes`인데 워크플로에 없음, 워크플로가 등록되지 않은 게이트를 돌림. 그리고 **전부 일치할 때 통과**하는 케이스. 여기에 두 가지를 더한다:

- **평범한 non-gate 스크립트가 있어도 통과해야 한다.** `dev`·`zip`·`test:watch`·`storybook`·`postinstall`이 있는 `package.json`으로 통과를 확인한다 — 이것이 없으면 "모든 스크립트가 표에 있어야 한다"는 영구 빨강 규칙이 슬그머니 되살아난다.
- **이름 규약을 따르는 고아 게이트는 잡힌다.** `scripts/`에 `*-gate.mjs`가 있는데 레지스트리에 없으면 FAIL. 규약 밖 이름은 잡히지 않는다는 것이 D4가 밝힌 경계이고, 그 사실을 확인하는 케이스도 함께 둔다 — 덮지 못하는 것을 덮은 척하지 않기 위해서다.

러너가 실패한 게이트의 출력을 **버리지 않고 보고하는지**도 단언한다. 출력을 버리면 빨강이 났을 때 무엇이 실패했는지 영영 알 수 없다.

**실행 순서와 산출물 신선도** — D4a가 세운 관계마다 픽스처 하나씩: 산출물 디렉터리가 없음, 이전 회차의 낡은 산출물이 남아 있음, 빌드가 실패함, `needs: build`인 게이트가 없을 때 빌드를 건너뜀. 핵심 단언 둘은 **빌드 실패 시 소비자가 `BLOCKED`이고 `N/A`가 아닌 것**, 그리고 **낡은 산출물이 통과를 만들지 못하는 것**이다. 후자는 소스를 바꾸고 빌드를 막은 채 소비자를 돌려 재현한다 — 이 픽스처가 없으면 D4a는 검사가 아니라 문장이다.

**겹친 실행** — 러너가 도는 중에 두 번째 러너를 띄운다. **두 회차가 서로 다른 디렉터리를 쓰고, 각 소비자가 자기 회차의 산출물만 재는 것**을 단언한다. 그리고 첫 러너를 빌드 도중에 죽여 그 자식이 계속 쓰게 만든 뒤, 두 번째 회차가 그 쓰기에 **전혀 영향받지 않는 것**을 본다 — 잠금 설계였다면 이 케이스가 정확히 뚫렸을 자리이고, 경로 분리가 실제로 그것을 없앴는지 여기서 증명된다.

**매니페스트 게이트** — 권한이 정확히 일치, 권한이 하나 더 있음, 권한이 하나 빠짐, manifest version이 3이 아님. 최소 크롬 버전은 네 가지: 하한과 같음(통과), 하한보다 낮음(FAIL), 값이 숫자가 아님(FAIL), 아예 없음(FAIL). CSP에 `unsafe-eval` 있음(FAIL). 권한 **추가**가 FAIL인 것과 **하한보다 낮은 버전**이 FAIL인 것이 이 게이트의 핵심이고, 전자는 부분집합 비교였다면, 후자는 존재 검사였다면 통과했을 자리다.

**오버플로 게이트** — 넘치는 요소가 있는 시드와 없는 시드. 여기에 **준비 상태 픽스처 둘**을 더한다: 시드가 실패해 화면이 비어 있는 경우와 지연 로드가 끝나지 않은 경우가 **통과하지 못하고 `FAIL`을 내는 것**. 빈 트리에는 넘치는 원소가 없으므로 이 두 케이스가 없으면 게이트는 아무것도 안 그려졌을 때 가장 잘 통과한다. 이 게이트는 실제 브라우저를 띄우므로 픽스처는 시드 상태이지 파일 트리가 아니고, 테스트는 브라우저 명령 쪽에 속한다.

**포맷 게이트** — 이미 포맷된 파일과 어긋난 파일. 후자가 종료 코드 1이어야 한다.

**포맷 커밋의 재현 증명** — 부모 트리에 고정 버전 포매터를 돌린 결과가 포맷 커밋의 트리와 같으면 통과. 그리고 **의미 있는 수정 한 줄을 그 커밋에 섞으면 이 증명이 실패하는 것**을 케이스로 둔다. 그것이 실패하지 않으면 이 증명은 `git show --stat`과 같은 값을 가진다.

**떠도는 프로미스** — `src/`에 await되지 않은 프로미스를 둔 픽스처가 **FAIL을 내야 한다.** 규칙이 설정 목록에 있다는 것과 규칙이 실제로 도는 것은 다르고, type-aware가 켜지지 않으면 이 규칙은 조용히 아무것도 하지 않는다.

**접근성 지문 베이스라인** — 네 가지: 새 진단이 하나 늘면 FAIL, 기존 진단이 사라지면 통과, **하나가 사라지고 다른 하나가 생겨 총계가 같은 경우가 FAIL**, 그리고 **위반 앞의 줄만 바뀌어 위치가 밀린 경우가 통과**. 셋째는 개수 베이스라인이었다면 통과했을 자리이고, 넷째는 줄·열을 지문에 넣었다면 실패했을 자리다 — 두 실패는 서로 반대 방향이라 한쪽 픽스처만으로는 다른 쪽을 잡지 못한다.

**테스트 분류 parity** — 넷. 핵심은 첫째다: **playwright를 직접 import하지 않으면서 `browser: yes`인 게이트를 자식 프로세스로 띄우는, 이름이 잘못된 테스트 파일**이 FAIL을 내야 한다. 이것이 이 스펙이 요구하는 seam에서 실제로 나타나는 형태이고, import를 세는 분류였다면 통과했을 자리다. 나머지 셋: playwright를 직접 import하면서 이름이 틀린 파일도 FAIL, 브라우저 픽스처가 `bun run test`의 대상에서 **제외**되는 것, 같은 픽스처가 `bun run test:browser`의 대상으로 **선택**되는 것. 뒤 둘이 없으면 두 glob이 실제로 배타적인지 아무것도 증명하지 않는다.

### 이 seam이 덮지 못하는 것 — 명시한다

게이트를 자식 프로세스로 재는 것은 게이트가 **무엇을 답하는가**를 덮지, 게이트가 재는 대상이 실제로 옳은지를 덮지 않는다. 예를 들어 매니페스트 게이트의 테스트는 "권한이 하나 더 있으면 FAIL"을 증명하지, 현재 권한 집합이 이 확장에 옳은 집합인지는 증명하지 않는다. 그것은 실제 브라우저에서 도는 smoke가 재는 것이고, 이 스펙은 그 경계를 넓히지 않는다.

기존 게이트 셋(`bundle-gate`·`writer-lane-gate`·`audit-smoke-barriers`)에는 이번에 테스트를 달지 않는다. 같은 seam으로 나중에 닫을 수 있는 구멍이고, 그 사실을 남은 위험으로 기록한다.

### 회귀를 재는 방식

포맷 전면 적용과 통합 테스트 이동은 동작을 바꾸지 않아야 하는 변경이다. 둘 다 전후로 **기존 스위트 전체와 실제 브라우저 검사**가 초록임을 증거로 든다.

포맷 커밋이 포맷만 바꿨다는 것은 D8의 **재현 절차**로 증명한다: 그 커밋의 부모를 깨끗한 트리에 꺼내 커밋이 고정한 바로 그 버전의 `oxfmt`를 돌리고, 결과 트리가 포맷 커밋의 트리와 정확히 같은지 본다. 검증 문서에 절차와 결과 트리 해시를 함께 적는다. **`git show --stat`은 증거가 아니다** — 경로와 줄 수만 보여 주므로 대량 포맷 커밋 안에 숨은 로직 수정이 그것을 그대로 만족시킨다. 서술용으로 덧붙이는 것은 무방하나 증명으로 쓰지 않는다.

## Out of Scope

- **meta-gate 층** — 게이트를 검사하는 게이트(스크립트 문법 건강성, 마크다운·링크 건강성, 스킬 참조 무결성, 리뷰어 봉쇄). 원본 하네스가 이것을 둔 이유는 그 저장소에 앱이 없어 자기 자신 말고는 검사할 대상이 없었기 때문이다. header-kit은 앱 그 자체라 그 전제가 없다.
- **stack manifest와 의존성 allowlist** — 선언되지 않은 패키지가 들어오면 FAIL하는 검사. 값이 없지 않지만 1인 유지보수 확장에 기계장치가 크다.
- **읽기 전용 리뷰어 서브에이전트 3종** — `.claude/agents/`. 이 저장소의 리뷰는 `/feature`의 codex 게이트가 맡고 있다.
- **`.claude/skills/`** — 프로젝트 스킬 체계. 게이트 표는 `docs/agents/`가 소유한다(D4).
- **`tsc`를 `oxlint`로 대체하는 것** — D5. 등가성이 측정된 뒤 별도 기능.
- **`sortTailwindcss` 켜기** — D8. 시각 게이트 확인 후 별도 슬라이스.
- **`scripts/`를 `tsconfig`에 포함시키는 것** — D13. 게이트 스크립트를 `.ts`로 옮기는 일이 딸려 온다. 이것을 하지 않는 대가는 명확하다: `scripts/`에서는 떠도는 프로미스가 잡히지 않는다.
- **기존 게이트 셋에 테스트 달기** — Testing Decisions가 남은 위험으로 기록한다.
- **`knip`(죽은 코드 검출) 도입** — WXT 플러그인이 `srcDir` 설정을 반영하지 못해 이 저장소에서 엔트리포인트를 죽은 파일로 오탐한다. 설정으로 고칠 수 있으나 이번 범위 밖이다.
- **WXT 버전 올리기** — 현재 0.20.27이고 0.21.x가 나와 있다. 이 기능과 무관하다.
- **`main`을 origin에 푸시하는 것** — 로컬 fast-forward만 되어 있다. 사람이 정한다.
- **접근성 규칙이 잡아낸 기존 위반을 전부 고치는 것** — 첫 실행의 진단 **지문**을 베이스라인으로 기록한다(D13a). 새 지문은 늘 수 없고, 기존 지문을 줄이는 것은 별도 작업이다.
- **키보드 조작과 접근명의 관측된 보장** — 실제 브라우저에서 초점 순서를 따라가고 접근명을 읽어 확인하는 것. 린트 지문은 "새 진단이 없다"까지만 주며, 그 이상을 주는 척하지 않는다(D13a). 이것을 원하면 브라우저 수준 수용 케이스가 필요하고 그것은 별도 기능이다.

## Further Notes

**이 저장소는 원본 하네스와 정반대 상태에서 출발한다.** 원본은 게이트 표 19행이 전부 `N/A`인 채로 코어만 완성돼 있었다 — 앱이 없어서다. header-kit은 게이트가 실제로 일곱 개 돌고 있는데 코어가 없다. 그래서 이 작업은 이식이 아니라 **거울상**이다. 원본에서 그대로 오는 것은 기계장치(마커, 라인 예산, 네 자리 일치, 자식 프로세스 seam)이고, 데이터(무엇이 게이트인가, 무엇이 스택인가, 무엇이 레이어인가)는 전부 이 저장소의 것으로 새로 쓴다.

**원본이 값비싸게 배운 것 하나를 그대로 가져온다.** 그 저장소의 결정 기록에 세 번 반복되는 문장이 있다 — 효과가 있었던 수는 증명을 계속하는 것이 아니라 증명해야 할 것을 **없애거나 거절하는** 것이었다. `@import`를 인라인으로 바꾼 것, 판정할 수 없는 버전 범위를 탐색 대신 거절한 것, 기억으로 쓴 allowlist를 지운 것이 전부 같은 모양이다. 이 스펙에서 그에 해당하는 자리는 D6의 픽스처 설계다 — 설정이 완전한지 세는 대신 설정이 실제로 거절하는지를 재고, 성립 전제(cwd 기준 해석)를 가정하지 않고 첫 티켓에서 잰다.

**게이트를 늘리는 일에는 대칭적인 위험이 있다.** 검사하지 않는 초록도 나쁘지만, 평범한 변경에 빨강을 내는 게이트도 나쁘다 — 후자를 고치는 유일한 길이 게이트를 고치는 것이 되기 때문이다. `dependency-cruiser`를 버린 이유가 전자이고, 성능 대조를 자문 행으로 내린 이유가 후자다. 새 게이트를 더할 때마다 두 방향을 다 물어야 한다.

**측정된 사실의 유효기간.** 이 스펙이 근거로 든 버전과 동작(`oxlint` 1.78.0 / `oxlint-tsgolint` 7.0.2001 / `oxfmt` 0.63.0, `dependency-cruiser`가 TS 7에서 0모듈을 검사하는 것, `oxlint`에 `import/no-restricted-paths`가 없는 것)은 2026-08-11에 실행으로 확인했다. 구현이 그와 다른 것을 만나면 그것이 스펙의 결함이지 구현의 재량이 아니다 — 다시 재고 스펙을 고친다.
