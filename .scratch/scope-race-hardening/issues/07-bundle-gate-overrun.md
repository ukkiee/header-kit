# 07 — 번들 게이트 초과분 처분

**What to build:** 팝업을 여는 사람이 지금 즉시 내려받는 바이트가 이 저장소가 스스로에게 건
한도를 넘었다. 넘긴 것 자체보다 나쁜 것은 **넘긴 기록이 없다**는 점이다 — 이 게이트의 한도는
지금까지 다섯 번 움직였고 매번 실측과 사용자 승인이 티켓 하나에 묶여 있었는데(스크립트 주석의
"한도 이력"), 이번 초과에는 그 줄이 없다. 이 티켓은 초과분의 출처를 실측으로 밝히고, 줄이거나
한도를 올리거나 둘 중 하나로 **기록을 되살린다**.

```
popup 즉시 로드 합계 590.2KB = baseline 386KB + 204.2KB (한도 +190KB) — FAIL
                                                          → 14.2KB 초과
```

기원은 `wide-ui-redesign`이다. 그 브랜치는 2026-07-28 사람 결정으로 정지됐고, 남긴 critical
셋은 이 슬러그가 티켓 01–06으로 받았다. 이 초과는 그때 함께 넘어온 미처리 건이다 — 릴리스
게이트가 `main`..HEAD 전체를 보므로(Stage 0 결정) **이 슬러그가 배를 띄우기 전에 반드시
마주친다.** 티켓 01에서 발견돼 분리됐다(사용자 결정 2026-07-30).

**Blocked by:** None — can start immediately. 티켓 01–06과 코드를 공유하지 않는다.
다만 **릴리스 게이트(Stage 5)보다 먼저** 끝나야 한다.

**Status:** ready-for-agent

- [ ] 초과분의 출처가 **실측으로** 밝혀져 있다 — `main`(`d142ec3`) 대비 즉시 로드 집합의
      **항목별 증감표**. "shadcn 때문"처럼 뭉뚱그린 귀속은 이 티켓을 닫지 못한다. 마지막
      재트리아지가 남긴 값은 180.5KB였고 지금이 204.2KB이므로, 설명해야 할 것은 그 23.7KB다.
- [ ] 즉시 집합의 큰 항목들에 대해 **지연 로드 가능성이 항목별로 판정**돼 있다. 특히
      `resolveAriaLabelledBy` 114.4KB(Base UI)와 `global` 449.5KB. 각 항목은 "지연 가능"이거나
      "불가 — 첫 페인트에 필요한 이유"로 결론이 나야 한다. 판정하지 않고 한도부터 올리지 않는다.
- [ ] 처분이 둘 중 하나로 끝난다.
      **(a) 줄인다** — 지연 가능으로 판정된 것을 실제로 지연시켜 한도 안에 들어온다.
      **(b) 한도를 올린다** — 사다리 관례를 그대로 밟는다: 실측 근거를 이 티켓에 남기고,
      `scripts/bundle-gate.mjs`의 "한도 이력" 주석에 한 줄을 더하며, **올리기 전에 사용자
      승인을 받는다.** 승인 없는 상향은 이 게이트를 게이트가 아니게 만든다.
- [ ] 상향을 골랐다면 그 근거가 **완화임을 숨기지 않는다.** 스크립트 주석이 앞선 다섯 중
      어느 것이 완화였고 어느 것이 아니었는지를 구분해 적어 두었다 — 그 정직함을 이어받는다.
- [ ] `bun run bundle-gate` PASS.
- [ ] 나머지 게이트에 회귀 없음 — 타입 검사 · 단위 · 빌드 · 스모크.
- [ ] 지연 로드로 무게를 옮겼다면, **옮긴 것이 첫 페인트를 늦추지 않았음**이 관측된다.
      스모크에 이미 팝업을 열어 재는 시나리오들이 있으므로 새 시임을 세우지 않는다.
