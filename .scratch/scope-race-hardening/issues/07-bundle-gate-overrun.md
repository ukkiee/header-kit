# 07 — 번들 게이트 초과분 처분

**What to build:** 팝업을 여는 사람이 지금 즉시 내려받는 바이트가 이 저장소가 스스로에게 건
한도를 넘었다. 넘긴 것 자체보다 나쁜 것은 **넘긴 기록이 없다**는 점이다 — 이 게이트의 한도는
지금까지 다섯 번 움직였고 매번 실측과 사용자 승인이 티켓 하나에 묶여 있었는데(스크립트 주석의
"한도 이력"), 이번 초과에는 그 줄이 없다. 이 티켓은 초과분의 출처를 실측으로 밝히고, 줄이거나
한도를 올리거나 둘 중 하나로 **기록을 되살린다**.

```
popup 즉시 로드 합계 590.2KB = baseline 386KB + 204.2KB (한도 +190KB) — FAIL
                                                          → 14.2KB 초과
```

기원은 `wide-ui-redesign`이다. 그 브랜치는 2026-07-28 사람 결정으로 정지됐고, 남긴 critical
셋은 이 슬러그가 티켓 01–06으로 받았다. 이 초과는 그때 함께 넘어온 미처리 건이다 — 릴리스
게이트가 `main`..HEAD 전체를 보므로(Stage 0 결정) **이 슬러그가 배를 띄우기 전에 반드시
마주친다.** 티켓 01에서 발견돼 분리됐다(사용자 결정 2026-07-30).

**Blocked by:** None — can start immediately. 티켓 01–06과 코드를 공유하지 않는다.

#### 구현 — 저장소가 이미 실측으로 기각한 두 가지를 피했다

`header-name-input.tsx`가 같은 문제를 먼저 겪고 근거를 남겨 두었다. 그대로 따랐다.

- **`React.lazy`를 쓰지 않는다.** lazy는 모듈이 도착해 있어도 첫 렌더에서 서스펜드했다가
  재시도하고 그 왕복이 **~250ms**였다(그 파일의 실측). 대신 받아 둔 컴포넌트를 모듈 스코프에
  두고 `useSyncExternalStore`로 곧바로 동기 렌더한다(그 방식 실측 0~7ms).
- **마운트 시점에 미리 받지 않는다.** 앞당긴 로드가 첫 페인트 **전에** 끼어들어 시작이
  62 → 85ms로 늘었다(같은 파일 실측). 이 티켓의 목적이 시작을 가볍게 하는 것인데 받는 시점을
  앞당겨 상쇄하면 앞뒤가 맞지 않는다.

대신 **의도 시점에 받는다** — 폼으로 가는 길목(`ruleFormIntentProps`)의 `onPointerEnter`·`onFocus`
에서 시작하고, 여는 문(`openRuleForm`)이 한 번 더 부른다. 길목은 셋이다: '규칙 추가' 버튼 둘과
**규칙 행 컨테이너**. 셋째를 행에 둔 것은 연필 아이콘까지 두 층(`RuleRow`·`ItemRow`)을 뚫는 대신
배선을 한 곳에 모으기 위해서이고, 행에 닿는 것 자체가 이미 편집 의도에 가깝다.

> **첫 판은 여기서 틀렸다.** '규칙 추가' 버튼 둘에만 손으로 복제해 붙이고 편집 경로를 빠뜨렸는데,
> 규칙이 있는 사용자에게는 편집이 지배적 진입점이다. 리뷰가 실측으로 잡았다. 고친 뒤 같은 잣대로
> 다시 쟀다 — **편집 연필 hover 300ms 후 자리표시 프레임 1/1/1 → 0/0/0.** (포인터 이동 없이
> 즉시 클릭하는 합성 경로는 여전히 2/1/1이다. 실사용에는 마우스의 pointerenter나 키보드의 focus가
> 항상 먼저 온다.) 복제 대신 소품 한 덩어리를 내보내는 것으로 바꿔 길목이 늘어도 빠뜨릴 자리를
> 줄였다.

**게이트에 계약으로 못 박았다** — `MUST_BE_DEFERRED`에 `rule-form`을 넣었다. 그 줄이 없으면
누군가 다시 정적 import해도 **크기 한도 안에만 들어오면 조용히 통과한다.**

#### 수용 기준 7 — 첫 페인트가 늦지 않았다

즉시 집합에서 59KB가 빠졌으므로 첫 페인트는 가벼워지기만 한다. 이 기준이 실제로 막으려는 것은
"무게를 옮겨 놓고 다시 앞당겨 받아 상쇄하는 것"인데, 위대로 **마운트 시점 선로드를 넣지
않았다.** 새 시임은 세우지 않았고 기존 시나리오로 관측했다 — 폼을 여는 시나리오 전부와, 폼
타이밍을 직접 재는 `N24c`가 통과한다(취소 reduced 58ms / lively 326ms, exit 창 260ms).

#### 한도 이력

한도가 움직이지 않았으므로 사다리에 칸이 늘지 않는다. 대신 `bundle-gate.mjs` 주석에 **여섯
번째 칸을 밟지 않았다**는 사실과 그 근거를 적고, 이 파일을 측정 정본 셋째로 등록했다.

#### 확정 — 고쳤다

**1. 편집 경로에 선로드가 없었다** (Standards S-2 / Spec S4). '규칙 추가' 버튼 둘에만 핸들러를
손으로 복제해 붙이고, 폼으로 가는 셋째 문인 편집 연필을 빠뜨렸다. 리뷰가 브라우저에서 쟀다 —
편집 연필 cold 2/1/1 프레임, **hover 300ms를 줘도 1/1/1**("아무도 듣고 있지 않으니 변화가 없다").
즉 "실제로는 자리표시가 보이지 않는다"는 내 주석이 **지배적 경로에서 거짓**이었다.
고침: 소품 한 덩어리(`ruleFormIntentProps`)를 내보내 세 길목이 같은 것을 쓰게 하고, 셋째를 규칙
행 컨테이너에 붙였다. 같은 잣대로 재측정 — **hover 300ms 후 0/0/0**.

**2. 자리표시 높이가 근거 없는 추정치였다** (Standards S-3). `min-h-48`(192px)로 두고 "같은 크기라
튀지 않는다"고 적었는데, 리뷰가 Storybook 정적 빌드 + 브라우저 실측으로 반증했다 — 실제 폼은
342px(Block·Redirect)에서 466px(응답 헤더), 기본 생성 폼 424px, 편집 래퍼 안에서는 442px 대 210px.
애니메이션 추적까지 떴다: `330ms h=209(내용 442) → 346ms 442로 스냅`. **주석이 막겠다고 적은 현상을
그 주석의 숫자가 만들고 있었다.** 고침: 실측 범위를 주석에 적고 384px(`min-h-96`)로 올렸다 —
범위 안이고 기본값에 가깝다. 그리고 종류마다 높이가 달라 **하나의 옳은 값이 없다**는 사실을
명시하고, 본선은 위 1번(자리표시가 보이는 일 자체를 없애는 것)임을 적었다.

**3. 실측 숫자를 소스 주석에 베껴 적었고 첫 사본이 이미 어긋났다** (Standards S-4).
`531.4/145.4`라고 적었는데 정본과 게이트 출력은 `531.8/145.8`이었다. `bundle-gate.mjs`가 같은
이유로 "숫자를 여기 옮겨 적지 않는다"를 세워 뒀는데 그 규칙이 예언한 드리프트가 규칙을 어긴 첫
사본에서 곧바로 실현됐다. 고침: 모듈 주석에서 수치를 빼고 정본을 가리킨다.
(검증자가 "관례 위반" 프레이밍은 반박했다 — 그 문장의 '여기'는 그 파일 자신이고, 같은 diff가
그 파일에도 숫자를 더했다. 남는 것은 산술 오류이고 그건 실재한다.)

#### 수용 기준 2 — 청크 이름과 판정 표의 관계 (Spec S2)

기준 2가 이름을 짚은 두 청크가 판정 표에 그 이름으로 나오지 않는다. 이유는 **청크 이름이 이 작업의
대상 그 자체이기 때문**이다 — 지연을 넣자 Base UI 덩어리의 앵커 모듈이 바뀌어
`resolveAriaLabelledBy-*`는 오늘 **1.9KB이자 지연 쪽**이고, 즉시 쪽의 큰 Base UI 덩어리는
`useOpenInteractionType-*` 112.6KB다. `global-*`도 마찬가지로 쪼개졌다. 그래서 표를 청크가 아니라
**패키지 단위**로 세웠고, 그것이 리비전을 넘나드는 유일한 안정 잣대다. 대응은 이렇다:

- 기준이 말한 `resolveAriaLabelledBy` 114.4KB · `global` 449.5KB의 Base UI 몫 → 표의
  **`@base-ui/react`(+`utils`) 208.4KB** 행이 덮는다(판정: 부분 지연 가능, 실측으로 실행).
- `global`의 나머지 → `react-dom` · `motion-*` · `tailwind-merge` · `@floating-ui/*` · 1차 코드 행.

표 여섯 행의 합은 580.9KB로 즉시 집합 591.0KB의 **98.3%**를 덮는다. 남는 ~10KB는 0.5KB 미만 항목의
꼬리다.

#### 수용 기준 1 — 귀속 방법 (재현 절차, Spec S7)

1. `git worktree add <tmp> d142ec3`, `node_modules` 심볼릭 링크, `bunx wxt prepare`.
2. 양쪽 트리의 `wxt.config.ts`에 `build: { sourcemap: true }`를 **임시로** 넣고 `bun run build`.
3. 즉시 집합을 게이트와 **같은 방법**으로 도출(`popup.html`의 엔트리·modulepreload를 뿌리로 정적
   import 전이 폐포).
4. 각 청크의 `.map`을 VLQ 디코드해 세그먼트가 덮는 생성 열 구간 길이를 그 소스에 더한다. 매핑
   없는 바이트는 `(unmapped)`로 따로 센다(숨기면 합계가 어긋난다).
5. `node_modules/<pkg>` / `src/<feature>` 단위로 묶어 양쪽을 대조.

합계가 게이트 출력과 일치하는지로 계량기를 검증했다(566.7 대 566.5 · 591.0 대 590.8 — 개행 계산
차이). 계량 스크립트는 일회성이라 저장소에 남기지 않았다. 위 절차로 재현된다.

#### 슬러그 Out of Scope 선언과의 화해 (Spec S8)

스펙은 "이 슬러그는 순전히 결함 교정이다 — **사용자에게 보이는 새 어포던스를 더하지 않는다**"고
선언했다. 이 티켓은 그 선언 밖 항목으로 붙었고(티켓 본문 참조), 처분 (a)는 사용자가 보는 것을
하나 바꾼다: 폼이 도착 전이면 빈 상자가 스친다. 화해는 이렇다 — **새 어포던스가 아니다.** 누를 수
있는 것도, 할 수 있는 일도 늘지 않았고, 위 실측대로 실사용 경로에서는 그리지도 않는다(0/0/0).
선언이 막으려던 것은 결함 교정에 기능을 얹는 것이고, 이것은 기능이 아니라 같은 기능을 늦게
받는 것이다. 대가가 0은 아니므로 여기 적어 둔다.
