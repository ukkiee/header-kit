# 05 — Scope Breadth를 authority 자리로

**What to build:** URL 패턴의 **경로 자리**에 도메인처럼 생긴 조각이 있는 Block Modification이
저장 전에 확인을 받는다. 지금은 그런 패턴이 '좁음'으로 통과한다 — 판정이 패턴 문자열 전체를
훑어 경로에 있는 도메인꼴 토큰을 호스트로 세기 때문이다. 사용자는 광고 도메인 하나를 막았다고
믿고 나가지만, 실제로는 방문하는 모든 사이트의 그 경로에서 요청이 사라진다. Block은 요청을
아예 없애는 유일한 종류라 이 오판이 페이지를 깨뜨린다. 이 티켓이 릴리스 r3의 R-1을 닫는다.

Scope Breadth 판정을 문자열 전체 스캔에서 **각 갈래의 authority 구간 스캔**으로 바꾼다.
설계 근거와 물린 두 대안(앵커 요구 · 위치까지 증명)은 `.scratch/scope-race-hardening/spec.md`의
D1에 있고, 용어 정의는 `CONTEXT.md`의 **Scope Breadth** 항목에 있다.

**Blocked by:** None — can start immediately. 다른 다섯과 코드를 공유하지 않는다.

**바꾼 것 하나.** 호스트 결합 판정을 문자열 전체 스캔에서 **authority 구간 스캔**으로 옮겼다.
`authoritySpan(text)`은 스킴 구분자 뒤부터 첫 경로 구분자 앞까지를 돌려주고, 정규식 조각일 수
있으므로 **문자 클래스 안쪽**의 `/`(`[^/]`의 것)와 **이스케이프**를 넘어간다 — 단 `\/`는 리터럴

중요하다: 자르는 동안에는 이스케이프가 온전해야 한다.

매치 방식별로:
- `domain` — 값 자체가 호스트이므로 값 전체를 authority로 본다(변화 없음).
- `prefix` — `prefixBreadth`가 이미 호스트 구간을 뽑아 쓰므로 의미가 바뀌지 않는다(손대지 않았다).
- `contains` — authority 구간만 본다. 경로 조각만 든 값은 이제 넓음이다.
- `regex` — **갈래마다 자기 authority 구간**을 본다.

**"한 행도 뒤집히지 않는다"를 실측으로 증명했다.** `ff274b2`의 옛 판정 테이블 파일을 그대로

#### 고친 것 셋 (전부 열린 실패 — 넓은데 `narrow`)

**1. 스킴 구분자를 `indexOf('://')`로 찾은 것 — 이 커밋이 만든 회귀 (Spec R-1, high).**
`indexOf`가 돌려주는 것은 **문자열 안의 첫 `://`**이고 스킴 구분자가 아니다. 리다이렉트·트래킹
엔드포인트를 막는 흔한 모양에는 `://`가 **쿼리 안에** 또 있어서, 구간이 쿼리 안에서 잘려 나오고
거기 있는 도메인이 호스트로 세어졌다. `ff274b2`에서 `wide`였던 넷이 `narrow`로 뒤집혔다:

```
^https?:\/\/[^\/]+\/u=https://ads\.example\.com\/     base wide → 이 커밋 narrow
[^\/]+\/u=https://ads\.example\.com\/                 base wide → narrow
.*\/u=https://ads\.example\.com\/                     base wide → narrow
^.*\/track\/https://ads\.example\.com\/px\.gif        base wide → narrow
```

첫 행은 `new RegExp(p).test('https://victim.test/u=https://ads.example.com/')`가 `true`다.
회귀가 조용히 통과한 이유는 51+6행 **어디도 경로·쿼리에 URL이 박힌 모양을 밟지 않았기** 때문이다.
고침: 왼쪽부터 한 번만 훑으면서 구분자를 먼저 만나면 거기서 끝낸다 — 구분자 뒤의 `://`에는
애초에 닿지 못한다. 별도 가드 조건이 아니라 스캔 순서로 해결된다.

**2. 구간이 `?`·`#`에서 끊기지 않은 것 (Standards R-2).** 쿼리 자리의 도메인이 호스트로 세어졌다.
`^https://[^/]*\?r=ads\.example\.com` → `narrow`인데 `[^/]`가 `/`를 넘지 못하므로 도메인이 쿼리에
있다는 것이 **패턴 문자열만으로 확정**된다. 같은 파일 `isHostBound` 주석이 호스트는 `/`·`:`·`?`·끝
으로 닫힌다고 스스로 규정한 것과도 어긋났다. 고침: 정규식에서는 `\?`·`\#`과 맨 `#`에서 끊고,
**맨 `?`에서는 끊지 않는다** — 정규식에서 그것은 수량자다(M4 변이가 이것을 증명했다).

**3. 리터럴 값을 정규식으로 읽은 것 (Spec R-2 / Standards R-3).** ADR 0008의 컴파일 매핑은
`contains`·`prefix`를 DNR **비정규식** `urlFilter`로 내려보내므로 그 값에서 `[`·`\`는 평범한
글자다. 정규식 독법으로 읽으면 `[`가 문자 클래스가 되어 안쪽의 `/`를 구분자로 세지 않고,
경로 조각만 든 부분 문자열이 통과했다 — **브래킷 하나가 가드레일을 끈다**:

```
/path.example.net/          wide  ← 이 티켓의 반례 4
[/path.example.net/         narrow  ← 대괄호 하나 붙였을 뿐
v1[/ads.example.com/beacon  narrow
x[a/b]ads.example.com/y     narrow
```

고침: `authoritySpan(text, reading)`을 두 독법으로 갈랐다. 부수로 `prefixBreadth`가 쓰던
`indexOf`+`split('/')` 잣대가 같은 함수로 합쳐져, 같은 리터럴 문자열이 두 방식에서 반대로
판정되던 것이 사라졌다(리드 2의 답).

M2가 5건이 아니라 3건인 것은 클래스형 둘(`[^/]*\?r=`)이 클래스 미인식으로도 닫히기 때문이다.
M4는 리뷰어의 경고("맨 `?`에서 끊으면 인라인 플래그 행이 뒤집힌다")를 실측으로 확인해 준다.

#### 반박된 것 셋 — 다시 열지 말 것

- **Standards R-1** (`/`를 넘는 와일드카드가 구간을 통과한다, `^https?://.*ads\.example\.com`):
  base=narrow, HEAD=narrow — **델타 0**. 이 커밋이 만든 것이 아니고, 조이는 형태가 플랜 게이트
  r1의 **R-4에서 사람이 reject한 앵커 강제**와 같다. Out of Scope 항목이 이것이다.
- **Standards R-4** (`:\/\/`로 이스케이프한 스킴이 `wide`로 오경보): 델타 0, **닫힌** 실패이고,
  근거로 인용한 문장이 `CONTEXT.md`에 실재하지 않는다(반박 에이전트가 grep으로 확인).
- **Standards R-3의 high/medium 프레이밍**: 브래킷 값을 실제 DNR `urlFilter` 시맨틱으로 컴파일해
  현실적 URL 40개에 물린 결과 직접 매칭 0건 — `[`가 리터럴이라 필터가 오히려 **좁아진다**.
  그래서 열린 방향이긴 하나 도달 폭이 좁아 low로 내려 고쳤다(Spec R-2와 같은 픽스).

#### 잔여로 남긴 것

`contains: &d=ads.example.com` → `narrow`. `?`·`#`은 RFC 3986 구분자라 자리를 증명하지만 `&`는
userinfo의 sub-delim으로도 허용되어 증명하지 못하고, 이 값에는 스킴 구분자가 없어 위치를 고정할
근거가 문자열 안에 없다 — 이미 못 박힌 D1 수용 한계(`ads.example.com/path` → narrow)와 같은
모양이다. `isHostBound` 주석에 명시했다.

#### 문서

`CONTEXT.md`에 **Authority 구간** 항목을 추가했다(Standards R-5). 코드가 `authority`를 새 도메인
용어로 도입했는데 유비쿼터스 언어에 없었고, AGENTS.md가 도메인 문서를 `CONTEXT.md` + `docs/adr/`로
못 박고 있다. 구간의 경계·두 독법·증명 범위를 한 항목에 적었다.

#### 스모크

N18l의 "확인 후 저장됨"만 `pollUntil` 없이 한 번 읽던 것을 형제 단언 관례에 맞췄다(두 축이 독립
적으로 같은 줄을 지적). `waitFormClosed`는 Cancel 버튼의 detach만 기다리므로 저장 완료의 신호가
아니다.
