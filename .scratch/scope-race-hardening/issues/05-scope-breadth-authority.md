# 05 — Scope Breadth를 authority 자리로

**What to build:** URL 패턴의 **경로 자리**에 도메인처럼 생긴 조각이 있는 Block Modification이
저장 전에 확인을 받는다. 지금은 그런 패턴이 '좁음'으로 통과한다 — 판정이 패턴 문자열 전체를
훑어 경로에 있는 도메인꼴 토큰을 호스트로 세기 때문이다. 사용자는 광고 도메인 하나를 막았다고
믿고 나가지만, 실제로는 방문하는 모든 사이트의 그 경로에서 요청이 사라진다. Block은 요청을
아예 없애는 유일한 종류라 이 오판이 페이지를 깨뜨린다. 이 티켓이 릴리스 r3의 R-1을 닫는다.

Scope Breadth 판정을 문자열 전체 스캔에서 **각 갈래의 authority 구간 스캔**으로 바꾼다.
설계 근거와 물린 두 대안(앵커 요구 · 위치까지 증명)은 `.scratch/scope-race-hardening/spec.md`의
D1에 있고, 용어 정의는 `CONTEXT.md`의 **Scope Breadth** 항목에 있다.

**Blocked by:** None — can start immediately. 다른 다섯과 코드를 공유하지 않는다.

**Status:** ready-for-agent

- [x] 호스트 결합 판정이 **authority 구간에서만** 이뤄진다 — 스킴 구분자 뒤부터 첫 경로 구분자
      앞까지, 스킴 구분자가 없으면 첫 경로 구분자 앞 전체.
- [x] 정규식은 지금처럼 문맥을 분배해 갈래로 편 뒤 **모든 갈래**가 각자의 authority에서 호스트에
      묶여야 좁다. 한 갈래라도 못 묶이면 확인을 받는다.
- [x] 포기 경로는 전부 넓음으로 떨어진다 — 갈래 상한 초과 · 대안 그룹 뒤 수량자 · 괄호 불일치.
      포기가 '좁음'으로 새는 길이 없다.
- [x] 도메인 매치 방식은 값 자체가 호스트이므로 값 전체를 authority로 본다. 접두 매치의 의미가
      바뀌지 않는다. 부분 문자열 매치는 authority 구간만 본다.
- [x] 판정 테이블에 반례 넷이 들어가고 전부 넓음으로 판정된다 — 그룹 안 갈래의 경로 토큰,
      호스트 자리가 와일드카드이고 경로에 도메인이 있는 모양, 스킴 뒤가 전부 와일드카드인 모양,
      경로 조각만 든 부분 문자열 값.
- [x] **기존 판정 테이블의 단언이 한 행도 뒤집히지 않는다.** 개발용 로컬 호스트, 서브도메인
      와일드카드, 스킴 없는 정규식, 문자 클래스·이스케이프 안쪽의 세로줄, 인라인 플래그 —
      전부 지금 판정 그대로다.
- [x] 규칙이 만들어지지 않는 패턴은 계속 저장이 막힌다. 넓은 스코프는 계속 저장을 막지 않고
      확인만 요구한다.
- [x] Block이 아닌 종류의 저장 흐름이 전혀 바뀌지 않는다.
- [x] 스모크의 첫 저장 확인 시나리오가 반례 하나를 태운다 — 그 패턴의 첫 저장이 저장하지 않고
      확인을 요구하고, 확인 뒤에 저장된다. **컴포넌트 테스트 시임을 새로 만들지 않는다**:
      이 저장소에는 컴포넌트 테스트가 하나도 없고, 스모크가 이미 더 높은 시임에서 같은 흐름을
      보고 있다.
- [x] 좁은 스코프가 확인 없이 저장되는 기존 스모크 단언이 그대로 통과한다 — 확인이 상시가 되면
      사용자가 읽지 않고 누르게 되고 경고의 값이 사라진다.
- [x] 남는 한계가 코드 주석에 적혀 있다: 이 판정이 증명하는 것은 **패턴 문자열 안에서의 위치**
      이지 실제 URL 안에서의 위치가 아니다. 앵커 없는 패턴은 여전히 쿼리·경로에 그 문자열이
      들어간 URL에도 걸린다. 이 한계는 알고 남기는 것이며 근거는 스펙 D1에 있다.
- [x] 전 게이트 green — 타입 검사 · 단위 417/417 · 빌드 · 스모크 130/130 · writer-lane.
      **번들 게이트는 티켓 07** (선재 실패, 바이트 동일).

**바꾼 것 하나.** 호스트 결합 판정을 문자열 전체 스캔에서 **authority 구간 스캔**으로 옮겼다.
`authoritySpan(text)`은 스킴 구분자 뒤부터 첫 경로 구분자 앞까지를 돌려주고, 정규식 조각일 수
있으므로 **문자 클래스 안쪽**의 `/`(`[^/]`의 것)와 **이스케이프**를 넘어간다 — 단 `\/`는 리터럴
경로 구분자이므로 거기서 끊는다. 구간을 먼저 자르고 나서 `\.`를 리터럴 점으로 되살리는 **순서**가
중요하다: 자르는 동안에는 이스케이프가 온전해야 한다.

매치 방식별로:
- `domain` — 값 자체가 호스트이므로 값 전체를 authority로 본다(변화 없음).
- `prefix` — `prefixBreadth`가 이미 호스트 구간을 뽑아 쓰므로 의미가 바뀌지 않는다(손대지 않았다).
- `contains` — authority 구간만 본다. 경로 조각만 든 값은 이제 넓음이다.
- `regex` — **갈래마다 자기 authority 구간**을 본다.

**"한 행도 뒤집히지 않는다"를 실측으로 증명했다.** `ff274b2`의 옛 판정 테이블 파일을 그대로
꺼내 **새 구현에 돌렸다** — 51행 전부 통과. 그리고 반례 넷이 **옛 구현에서 실제로 `narrow`였고
새 구현에서 `wide`**임을 옛 구현을 임시로 나란히 두고 확인했다. 즉 이 넷을 고친 것이 authority
구간 변경이지, 이미 있던 `.invalid` 탐침이 아니다.

**반례 넷** (전부 탐침을 피하면서 모든 호스트에 걸린다):
1. 그룹 안 갈래의 **경로** 토큰 — `^(https://ads\.example\.net/|https://.*\.com/path\.example\.net/)`
2. 호스트 자리가 와일드카드, 도메인은 경로에 — `^https://[^/]+/ads\.example\.com/`
3. 스킴 뒤 호스트 자리가 전부 와일드카드 — `^https?://.*/ads\.example\.com`
4. 부분 문자열이 경로 조각만 — `contains: /path.example.net/`

**부수로 좁아진 것 하나**: `^https?://localhost:3000/api`(regex)가 이제 좁음이다. 전체 스캔에서는
`head`가 `^https`여서 로컬 호스트 판정에 닿지 못했다. 기존 테이블에 그 행이 없어 뒤집힘은
아니고, 개발 호스트는 기기 하나에 묶여 있으므로 의도한 방향이다. 새 행으로 못 박았다.

**경계 입력을 직접 찔러 봤다** — 이스케이프된 역슬래시 뒤 슬래시, 클래스 안의 `://`, 스킴 상대
`//host/path`, 닫히지 않은 클래스, 빈 authority, 쿼리·프래그먼트가 경로보다 먼저 오는 값, 중첩
브래킷. 여덟 입력 모두 세 판정 중 하나로 떨어지고 크래시하지 않는다. (다만 각 입력의 **판정이
옳은지**는 리뷰가 봐야 할 항목으로 남는다.)

**스모크 N18l 추가** — 경로 자리에 도메인이 있는 정규식 Block의 첫 Save가 저장하지 않고 확인을
요구하고, **확인 뒤에는 저장된다**(`wide`는 금지가 아니라 확인이라는 뜻이므로 뒤쪽까지 본다).
N18i의 "좁은 스코프는 확인 없이 저장" 단언도 그대로 통과한다 — 확인이 상시가 되면 경고의 값이
사라진다.

**남는 한계를 코드 주석에 적었다** (`isHostBound` 위). 이 판정이 증명하는 것은 패턴 문자열
안에서의 위치이지 실제 URL 안에서의 위치가 아니다. `ads.example.com/path`는 좁음이지만
`https://victim.test/ads.example.com/path`에도 매칭된다. 플랜 게이트 r1의 R-4가 이 구멍을 다시
제기했고 사람이 reject했다 — 어느 형태로 조여도 기존 아홉 행이 뒤집히고 그중 셋이 `contains`인데
ADR 0008이 폼 기본값을 `contains`로 정했으므로, 확인이 상시가 되어 가드레일이 죽는다. 판정을
테이블에 행으로 못 박아 두었으니 나중에 조일 때 무엇이 바뀌는지가 그 자리에서 읽힌다.
