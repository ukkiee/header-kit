# 프로필 메타 편집 되살리기 + 삭제 규약 통일

Status: done

## 문제

ADR 0017이 시안에 컨트롤이 없다는 이유로 프로필의 이름 변경·색 변경·복제·삭제 넷을
한꺼번에 없앴다. 삭제는 그 뒤 개정으로 돌아왔지만 이름과 색은 남았고, 그 대가가 실제로
드러났다: **만들 때 낸 오타나 팔레트가 자동으로 돌려준 색을 되돌리는 유일한 길이 프로필을
지우고 규칙을 다시 만드는 것**이다. 삭제를 되살린 개정이 없앤 것과 정확히 같은 종류의
대가다 — 되돌릴 수 없는 실수를 없애려던 결정이 더 큰 되돌림을 강요한다.

같은 시기에 파괴적 동작의 규약도 갈라져 있었다. 프로필 삭제·백업 한 행 삭제·클라우드
삭제·전체 초기화는 2단 확인인데 **규칙 삭제만** 한 번에 지우고 되돌리기를 토스트가 들었다.
어느 클릭이 되돌릴 수 없는지를 표면마다 다시 배워야 한다.

## 하는 일

1. 이름 변경 — 목록 행의 인라인 입력. 트림 + 빈 이름 거절, **중복 허용**.
2. 색 변경 — 편집 중에만 스와치가 버튼이 되어 팔레트 10색 + 자유 선택 팝오버를 연다.
   값은 `#rrggbb`로 접는다.
3. 삭제 규약 통일 — 규칙 삭제를 2단 확인으로, Undo 토스트와 `restore-modification` 퇴역.
4. 백업 히스토리 삭제의 되물음을 아이콘으로, 클라우드 삭제·전체 초기화의 **성공** 알림을
   토스트로.

## 하지 않는 일

- **복제.** 되돌림의 대가가 아니라 편의다.
- **백업 복원의 실행 취소 토스트 퇴역.** 되묻는 값은 되돌릴 수 **없는** 동작에 지불한다.
- **실패 알림의 토스트 이전.** 셸이 조건 없이 초록이고 제목이 한 줄로 잘리며, 실패는 다시
  눌러야 할 일이라 스스로 사라지면 안 된다.
- **정렬 컨트롤.** 규칙 순서는 우선순위다 (ADR 0019).

## 사용자가 정한 것 (이 대화가 정본)

| 물음 | 답 | 근거 |
|---|---|---|
| 이름 중복 | **허용** | 생성기와 가져오기가 이미 중복을 만든다 — 막으면 이미 있는 충돌을 고칠 길이 사라진다. 한 번 "거절"로 정했다가 뒤집었다 |
| 색 컨트롤 자리 | **이름 편집 중의 스와치** | 264px 열에 아이콘을 상시로 더할 수 없다. 새로 드는 자리 0 |
| 클라우드·초기화 알림 | **결과 알림만 토스트로** | 되물음은 인라인 2단계 그대로 |
| 백업 히스토리 되물음 | **아이콘** | 텍스트 버튼으로 부풀어 옆 아이콘을 밀어냈다 |
| 규칙 삭제 | **2단 확인, Undo 퇴역** | 우려를 전달했고 사용자가 재확인했다 |

## 계약

- 정규화는 `normalizeProfileName` · `normalizeProfileColor` **하나씩**이고 화면과 명령이
  같은 함수를 부른다. 화면이 자기 규칙으로 먼저 거르면 메시지로 직접 보낸 값만 다른 문을 지난다.
- 거절과 무변화는 둘 다 상태 그대로다 — 빈 이름을 실패 배너로 알릴 일이 아니다.
- 명령은 커밋 시점에 **한 번만**. 이름은 Enter·blur, 색은 팔레트 클릭이나 팝오버 닫힘.
- 편집을 열고 닫아도 **행 높이가 바뀌지 않는다.**
- 자유 선택은 지연 청크이고 `bundle-gate`가 문다.

## 검증

- `commands.test.ts` — 정규화·무변화·중복 허용 (+8 케이스)

- 스모크 N20a (2단 확인 + 실체화 값) · N20b (되물음은 행마다 따로)
- `bun run gate` 16행

## 남은 자리

- `restoreModification`이 사라지면서 "삭제한 규칙을 실체화 값까지 그대로 되살리는" 능력이
  앱에 없다. 되살릴 계획은 없다 — 2단 확인이 그 자리를 대신한다.
- N46(정지 흐림 색)이 부하가 걸린 독립 실행에서 드물게 거짓 빨강을 낸다. **진단하지 않았다.**
