# ui-stack-migration — Base UI 1.6 승격 + shadcn/ui 채택 + 디자인 감사 반영

**Triage:** ready-for-agent

## Problem Statement

프리미티브 계층이 두 가지 이유로 뒤처져 있다.

첫째, Base UI가 `1.0.0-rc.0`에 멈춰 있다. 정식 1.0에서 패키지 이름이 `@base-ui-components/react`에서 `@base-ui/react`로 바뀌었고 그 뒤로 마이너가 여섯 번 올라 지금 최신은 1.6.0이다. rc에 머무는 동안 쌓인 접근성·포커스 수정이 전부 반영되지 않았다.

둘째, 그 위의 스타일·변형·조합이 전부 자체 구현이다(`src/ui/` 21개). ADR 0011이 프리미티브를 Base UI로 일원화했지만 shadcn/ui는 도입하지 않았는데, 그때는 shadcn이 Radix 기반이라 채택이 곧 두 번째 프리미티브 계층을 들이는 일이었기 때문이다. 2026년 7월 shadcn의 기본이 Base UI로 바뀌면서 그 전제가 사라졌다 — 이제는 이미 쓰는 프리미티브 위에 얹힌다.

동시에 UI 자체에도 손볼 곳이 있다. 규칙 행의 편집·삭제가 호버 전에는 아예 보이지 않아 터치·펜 입력과 처음 쓰는 사용자에게 편집 경로가 발견 불가였고, 사이드바의 비활성 프로필 점은 흰 배경 대비 1.51:1로 상태를 색·명도로만 전달했다.

## Solution

Base UI를 1.6으로 승격하고, 프리미티브를 shadcn/ui 소스로 교체한다. shadcn 소스는 **수정하지 않고** 이 저장소 고유 계약(모션·시맨틱·크기·i18n)은 앱 레벨 조합 파일이 진다 — 재복사가 곧 갱신이 되게 하기 위해서다. 결정과 근거는 ADR 0014.

교체하는 김에 `/ui-review` 감사에서 나온 것 중 같은 파일을 여는 항목을 함께 반영한다(행 액션 노출, 프로필 점 대비·형태, 배너 행간, 죽은 코드 제거).

## User Stories

1. As a 사용자, I want 규칙 행의 편집·삭제가 마우스를 올리기 전에도 보이기를, so that 편집할 수 있다는 사실을 우연히 발견하지 않아도 된다
2. As a 저시력 사용자, I want 프로필의 켜짐·꺼짐이 색 말고도 구분되기를, so that 그레이스케일에서도 어느 프로필이 활성인지 읽는다
3. As a 사용자, I want 팝업이 지금과 똑같은 크기·밀도로 열리기를, so that 교체를 눈치채지 못한다
4. As a 감도 설정 사용자, I want 애니메이션이 여전히 부재하기를, so that shadcn 도입이 감도 계약을 깨지 않는다
5. As a 유지보수자, I want shadcn을 재복사해도 수정을 반복하지 않기를, so that 업스트림 갱신이 실제로 갱신이 된다

## Non-goals

- 테이블·차트·리치텍스트·대시보드·컴포지트(Coss UI) 도입 — 이 확장에 해당 concern이 없다
- 디자인 언어 자체의 변경 — 단일 blue accent, 무그림자, 시스템 폰트는 그대로다
- 감사 findings 전체 반영 — 같은 파일을 여는 것만 이번에 하고 나머지(배너 위계·툴팁·전송 패널 범위)는 별도 티켓
