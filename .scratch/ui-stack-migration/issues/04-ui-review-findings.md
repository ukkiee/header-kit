# 04 — /ui-review 감사 결과와 반영 범위

**What to build:** 마이그레이션 직전 상태의 UI를 16개 규칙으로 감사하고, 프리미티브를 교체하며 같은 파일을 여는 항목을 함께 고친다.

**Status:** partially done — 반영 4건 완료, 이월 4건

감사는 교체 **이전** 화면(`scripts/ui-diag.mjs` 스크린샷 6장: 팝업 라이트/다크, 탭 라이트/다크, 패널 펼침, 경계 18프로필)과 소스를 함께 읽고 수행했다. 대비는 토큰 값에서 직접 계산했다.

## 반영한 것

### #1 행의 편집·삭제가 호버 전에는 존재하지 않았다 (High, UI-03)

`rule-row.tsx`의 액션 묶음이 `opacity-0`이라 진단 스크린샷 6장 어디에도 편집·삭제 아이콘이 없었다. 규칙 편집은 이 앱의 핵심 동작인데 그 경로를 호버로만 발견할 수 있었고, 터치·펜에는 호버가 없다.

→ 기본 `opacity-60`으로 존재만 알리고 호버·포커스에서 100%. 완전한 0은 "읽기 모드 최소 소음"(ADR 0006)을 사는 대가가 너무 컸다. 스모크 **N17a**의 단언을 `idle === '0'`에서 `'0.6'`으로 바꾸며 이유를 주석에 남겼다 — 0으로 되돌아가면 실패한다.

### #2 비활성 프로필 점이 1.51:1이고 상태가 색으로만 전달됐다 (High, UI-07·UI-09)

`profile-dot.tsx`의 비활성 색 `zinc-300`(#d2d2d7)은 흰 배경 대비 **1.51:1**로, 상태를 나르는 비텍스트 요소의 하한 3:1에 한참 못 미쳤다. 활성 점은 프로필 색(#2563eb 5.17:1 · #d97706 3.19:1 · #16a34a 3.30:1 — 이들은 통과)이라 둘의 차이가 색·명도뿐이었다.

→ 비활성을 `zinc-400`(#86868b, **3.62:1**) 테두리 원으로, 활성은 채운 원으로. 색을 지워도 채움/테두리가 남는다. 6px 원에서는 형태 차이가 뭉개져 `size-2`로 키웠다. 상태 문자열 자체는 `profileSelectLabel`이 aria-label로 이미 전달하고 있었다 — 고친 것은 시각 채널이다.

### #4 `text-[11px]`이 line-height를 데려오지 않았다 (Medium, UI-16)

Tailwind 임의값은 font-size만 설정하고 행간은 부모에서 상속된다. 배너는 이 앱에서 실제로 여러 줄이 되는 거의 유일한 본문이다.

→ 새 `alert-banner.tsx`의 size 축이 행간을 함께 낸다(`text-[11px] leading-relaxed` / `text-xs leading-relaxed`).

### #7 `KindLabel`이 죽은 코드였고 되살리면 대비 미달이었다 (Low, UI-05)

사용처가 자기 스토리뿐이었다. 게다가 `microCaption`은 `zinc-400` + `text-[10px]` = **3.62:1**로 일반 텍스트 기준 4.5:1에 미달이라, 누군가 "이미 있는 캡션 스타일"로 채택하면 대비 미달이 화면에 들어올 수 있었다.

→ `kind-label.tsx`·스토리·`microCaption` 토큰을 함께 삭제.

## 보존하기로 한 것

감사에서 확인된 강점이라 교체 중에도 지켰다.

- **단일 accent가 실제로 지켜지고 있었다.** 행 종류 배지는 `bg-blue-50/text-blue-700` 하나이고 종류별 색 분기가 없다 — 다른 색은 상태(amber 주의 · red 제외/오류 · green 이상 없음)에만 쓴다.
- 본문 `zinc-900`(#1d1d1f)은 순흑이 아닌 near-black(UI-14), 보조 `zinc-500` 5.07:1, 배너 세 종 4.8~6.3:1.
- 무그림자 + 보더·명도로만 표면을 나누는 원칙(UI-05).
- 포커스 링이 한 토큰(`focusRing`, #0071e3 **4.70:1**)에서 나와 버튼·칩·아이콘버튼·그립이 같은 오프셋을 쓴다. shadcn 기본은 `ring-3`이라 교체 후 갈라지지 않는지 확인이 필요하다.
