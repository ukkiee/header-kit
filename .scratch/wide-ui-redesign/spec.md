# wide-ui-redesign — 다크 개발자도구 셸 + 새 규칙 종류·테마·백업 제어

**Triage:** ready-for-agent

원천: claude_design 프로젝트 "Mod Header 크롬 확장프로그램 디자인"
(`HeaderKit 확장 UI.dc.html` → `RulePopup 아코디언` → `RuleForm`). 설계 결정의 정본은 `.scratch/wide-ui-redesign/decisions.md`, 아키텍처 개정은 `docs/adr/0015-wide-ui-redesign.md`.

## Problem Statement

지금 HeaderKit의 UI는 밝은 미니멀 톤이다. 규칙을 자주 만지는 개발자 사용자에게는 (1) 화면이 개발자도구답게 어둡고 밀도 높지 않고, (2) 탭 앱의 넓은 공간이 밝은 좁은 셸을 그대로 늘린 것이라 넓이를 살리지 못하며, (3) OS가 라이트여도 확장만 다크로 고정할 방법이 없다. 기능 면에서도 자주 쓰는 조작 — User-Agent 바꾸기, 특정 요청 통째로 차단하기, 이름만으로 헤더 지우기 — 이 규칙 종류로 없어서 매번 우회해야 하고, 백업이 항상 계정 동기화를 타서 이 브라우저에만 두고 싶을 때 끌 수가 없다.

## Solution

가져온 다크 개발자도구 디자인을 두 표면(팝업·탭 앱)이 공유하는 셸에 입힌다. 탭 앱은 넓은 2열 레이아웃(레일 + 프로필 열 + 본문)으로 펴지고, 팝업은 같은 다크 셸을 760×580 안에 담는다. 규칙 목록은 아코디언 카드로, 행의 수정 아이콘을 누르면 그 규칙이 맨 위로 올라오며 폼이 인라인으로 펼쳐지고 저장하면 접혀 두 줄 요약으로 돌아온다.

규칙 종류에 **User-Agent 변경**, **요청 차단(Block)**, **헤더 삭제(Header Removal)** 를 더한다. 설정 화면에 **테마 스위치(다크/라이트/시스템)**, 배지 표시 토글, 읽기 전용 단축키 목록, 언어 선택(ko/en)을 둔다. 백업 화면에 JSON 내보내기/가져오기, **동기화 저장 스위치(sync↔local)**, 백업 히스토리, 2단계 전체 초기화를 둔다.

## User Stories

1. As a 개발자 사용자, I want 확장이 어두운 개발자도구 톤으로 보이기를, so that 종일 켜 두는 도구가 눈에 편하고 코드 편집기와 어울린다.
2. As a 탭 앱 사용자, I want 넓은 화면에서 프로필 열과 규칙 본문이 나란히 펴지기를, so that 스크롤 없이 더 많은 규칙을 한눈에 본다.
3. As a 팝업 사용자, I want 팝업이 지금과 같은 760×580 크기와 밀도로 열리기를, so that Chrome 팝업 한계 안에서 익숙하게 쓴다.
4. As a 사용자, I want 규칙 행의 수정 아이콘을 누르면 그 규칙이 맨 위로 올라와 폼이 펼쳐지기를, so that 편집 중인 규칙을 목록에서 잃지 않는다.
5. As a 사용자, I want 저장하면 폼이 접혀 두 줄 요약으로 돌아오기를, so that 편집이 끝났음을 바로 안다.
6. As a 사용자, I want 규칙 행에서 종류 뱃지·주요 값·URL·조건 칩을 두 줄로 읽기를, so that 열지 않고도 그 규칙이 무엇을 하는지 안다.
7. As a 사용자, I want 규칙 행의 토글로 즉시 켜고 끄기를, so that 폼을 열지 않고 규칙을 잠시 죽인다.
8. As a 사용자, I want 규칙 행의 삭제 아이콘으로 규칙을 지우기를, so that 필요 없는 규칙을 정리한다.
9. As a 사용자, I want User-Agent 변경 규칙을 만들기를, so that 특정 URL에서 브라우저 UA를 위장해 테스트한다.
10. As a 사용자, I want 요청 차단 규칙을 만들기를, so that 트래킹·광고·특정 엔드포인트 요청을 아예 막는다.
11. As a 사용자, I want 요청 차단 규칙은 이름·값 없이 URL 스코프만 받기를, so that 무엇을 차단할지 URL로만 정한다.
12. As a 사용자, I want 헤더 삭제 규칙을 이름만으로 만들기를, so that 요청·응답 어느 쪽에 있든 그 헤더가 사라진다.
13. As a 사용자, I want 각 규칙 종류가 자기에 맞는 필드만 보이기를(차단은 이름·값 없음, 삭제는 이름만, UA는 값만), so that 쓸모없는 입력에 헷갈리지 않는다.
14. As a 사용자, I want Set-Cookie 규칙에서 Domain·Path·Max-Age·SameSite·Secure·HttpOnly 속성을 정하기를, so that 응답 쿠키를 세밀하게 변조한다.
15. As a 사용자, I want URL 패턴을 와일드카드 또는 정규식으로 고르기를, so that 넓게 또는 정밀하게 스코프를 잡는다.
16. As a 사용자, I want 리소스 타입과 요청 메서드를 칩으로 골라 좁히기를, so that 규칙이 원하는 요청에만 걸린다.
17. As a 사용자, I want "저장 후 바로 활성화" 토글이 있기를, so that 만들자마자 켜거나 꺼진 채로 둘 수 있다.
18. As a 사용자, I want 규칙이 없을 때 빈 상태 안내와 추가 버튼을 보기를, so that 처음에 무엇을 할지 안다.

20. As a 사용자, I want 레일 하단에 적용 중인 규칙 총수를 보기를, so that 지금 몇 개가 실제로 걸려 있는지 안다.
21. As a 사용자, I want 프로필 열에서 검색으로 프로필을 거르기를, so that 프로필이 많아도 빨리 찾는다.

## Implementation Decisions

### 도메인 모델 (src/core)

- **새 Modification 종류 세 개**를 스키마 union과 생성기(model.ts)에 추가한다.
  - **User-Agent**: 값 하나(`value`)만 갖고 헤더 이름은 `User-Agent` 고정. URL 스코프·Condition은 다른 종류와 동일.
  - **Block**: 이름·값·mode 없음. URL 스코프와 Condition만. 유효한 최소 규칙이 URL 스코프뿐이다.
  - **Header Removal**: 헤더 이름(`name`)만. 값·mode 없음.
- **Compile 계약 (compile.ts)**:
  - User-Agent → `modifyHeaders` 요청 헤더 하나(`User-Agent` set/override), 기존 request-header 경로 재사용.
  - Block → dNR `{ action: { type: 'block' } }`. 조건 조립(regexFilter/urlFilter, resourceTypes, requestMethods, initiatorDomains, tab/excluded)은 기존 종류와 같은 조립기를 탄다.
- **Block 최소 가드레일 (R-4)**: Block은 요청을 통째로 막는 유일한 파괴적 종류라, 슬라이스 전에 최소 안전 계약을 확정한다.
  - **넓은 스코프 감지**: 전역 와일드카드(`*://*/*`, `<all_urls>` 등)나 광범위 정규식(도메인 앵커 없이 모든 호스트에 매칭)을 순수 함수로 판정한다.
  - **경고+확인**: 넓은 스코프 Block을 저장하려 하면 폼이 경고를 띄우고 명시적 확인을 요구한다.
  - **실효 스코프 상시 표시**: 규칙 행이 실효 URL 스코프를 항상 보여, 넓은 Block이 목록에서 드러난다.
  - **일시정지 복구**: 전역 Pause가 Block도 함께 멈춘다(모든 종류 공통) — 페이지가 깨졌을 때의 즉시 탈출구.
  - 보호 URL 허용목록·자동 복구 등 더 무거운 안전장치는 이월(Out of Scope).
  - Header Removal → dNR 규칙 하나가 `action.requestHeaders`와 `action.responseHeaders`에 각각 `{ operation: 'remove' }`를 함께 낸다. (기존 request/response-header + `emptyMeans:'remove'` 경로는 그대로 둔다 — 이건 별도 어포던스.)
- **Validation (rule-validation.ts)**: Block은 이름·값을 요구하지 않고 URL 스코프만 필수. Header Removal은 이름 필수·값 금지. User-Agent는 값 필수. 기존 필수-필드 포커스 흐름(첫 누락 입력으로 포커스)에 새 종류의 필수 필드를 매핑.
- **Summary (summary.ts)**: 새 종류의 행 요약 문자열(예: 'UA …', '요청 차단', '삭제 <name>')과 종류 뱃지(UA/BLOCK/DEL) 색을 더한다. 적용 규칙 총수(레일 하단)는 기존 summary가 이미 내는 값.
- **툴바 배지 (badge.ts) — 적용-규칙 카운터로 변경 (R-5)**: 현재 `computeBadge`는 프로필 표시기다(일시정지→'II', 활성 1개→그 프로필 짧은 라벨, ≥2→활성 **프로필 수**). 디자인 설정 라벨이 "적용 중인 규칙 수"이므로, 배지를 **재조정된 컴파일 요약의 적용 규칙 수**로 급전한다. 일시정지→'II'(일시정지색), 적용 0→빈 텍스트, N개 적용→N. 배지 표시 토글은 이 배지의 표시 여부(on/off)만 제어한다. quota·컴파일로 일부 규칙이 빠진 경우(부분 스킵)에도 배지는 **실제 적용된 수**를 보여 라벨과 값이 어긋나지 않는다.
- **버전 호환성 계약 (schema.ts, persist.ts, transfer.ts) (R-2)**: 현재 `persist`는 `schemaVersion === SCHEMA_VERSION` 정확 일치를 요구하고 `transfer`는 "format v1만 읽음, 더 높은 버전 거부"다. 새 종류 세 개는 이 포맷에 **추가**되므로:
  - **SCHEMA_VERSION과 export format 버전을 하나 올린다**(v1→v2). 새 종류를 담은 상태·내보내기 파일은 v2로 기록된다.
  - **명명된 v1→v2 전방 마이그레이션 (R2-2)**: storage.local의 **권위 있는 v1 상태**를 v2로 올리는 마이그레이션을 둔다. 기존 5종은 형태가 그대로라 마이그레이션은 버전 스탬프를 올리는 것이 핵심이며, **모든 프로필·규칙을 보존**한다. 검증에 성공한 뒤에만 v2로 persist하고, **마이그레이션 실패 시 default 프로필로 대체하지 않는다**(원본 v1을 그대로 두고 오류를 표면화). 즉 현재의 "버전 불일치 → default 폴백"을 v1 상태에는 적용하지 않는다.
  - **미지의 미래 포맷은 변형 없이 거부한다** — 이 v2 리더가 더 높은 버전(v3+) 상태를 만나면 기존 데이터를 **지우거나 default로 폴백하지 않고** 그대로 보존하며 "더 새 버전" 상태로 둔다.
  - **import의 미지 종류는 조용히 버리지 않고** 명시적 오류로 거부한다(퇴역 종류는 명명된 마이그레이션으로만 보존). 스펙 앞부분의 "조용히 버린다"는 이 계약으로 대체한다.
  - **경계**: 이미 배포된 구버전으로의 롤백(다운그레이드)은 그 구버전 코드가 정하므로 소급 보장 불가 — v0.1.0 미배포라 실사용 위험은 낮다. 이 계약은 v2 이후의 전방 안전만 정의한다.
- **Transfer/Backup 마이그레이션 (transfer.ts, backup.ts)**: import·load 검증이 새 종류를 v2로 통과시킨다.

### 테마 (새 상태 + 순수 함수)

- StoredState에 **theme 선호값**(`'dark' | 'light' | 'system'`, 기본 `'system'`)을 더한다. 커맨드로 바꾸고 persist에 저장한다.
- **테마 해석은 순수 함수**로 자른다: `(pref, systemPrefersDark) → 'dark' | 'light'`. 앱 셸이 이 결과를 루트의 `data-theme`로 반영한다(global.css의 기존 `[data-theme]` 훅 재사용). '시스템'일 때만 `prefers-color-scheme`를 구독.
- 다크 팔레트를 디자인 값으로 교체하고 라이트를 파생. accent를 디자인 blue로. Geist·Geist Mono를 로컬 번들.

### 백업 동기화 스위치 (R-1 — 단순 계약)

원자적 이관·프라이버시 즉시삭제·직렬 writer 같은 무거운 트랜잭션 기계는 v0.1.0에 과설계라, 스위치를 **앞으로의 백업 위치만 정하는** 단순 계약으로 둔다. 이 단순화가 R2-1(커밋-후 삭제 실패)·R2-4(자동 백업과의 경쟁)를 구조에서 없앤다 — 암묵적 이관이 없으니 경쟁할 이관도 없다.

- StoredState(또는 백업 설정)에 **sync 저장 여부** 플래그를 더한다. backup.ts의 **앞으로의** 저장 대상이 이 플래그에 따라 storage.sync ↔ storage.local로 갈린다. 스냅샷 매니페스트·복원·quota 계산은 대상 저장소에 맞춘다.
- **기존 설치 기본값**: sync ON (현재 백업이 항상 storage.sync를 쓰므로 기존 히스토리가 그대로 보인다).
- **토글은 기존 히스토리를 이관하지 않는다**: 스냅샷은 만들어진 저장소에 그대로 남는다. UI 히스토리는 **활성(현재 선택된) 저장소**의 것을 보여준다. 저장소를 다시 바꾸면 그쪽 히스토리가 다시 보인다 — 어느 것도 삭제되거나 옮겨지지 않는다.
- **클라우드 삭제는 별도의 명시적 동작**: sync를 끄는 것과 클라우드 백업을 지우는 것을 분리한다. sync OFF는 앞으로를 local로 돌릴 뿐이고, 클라우드 잔재를 지우려면 **"클라우드 백업 삭제" 버튼**(자체 확인 + 삭제 검증)을 따로 누른다. 이 삭제만은 성공을 검증하고 실패 시 오류를 표면화한다 — "이 브라우저에만"이라는 거짓 표시가 나올 여지가 없다.
- 사용자 대면 라벨 '클라우드 동기화', 상태 문구는 켜짐/꺼짐 + 클라우드에 백업이 남아 있는지에 따라.

### 설정·백업 화면

- 설정: 테마 스위치, 배지 표시 토글(기존 badge 로직에 연결), 읽기 전용 단축키 목록(현재 등록된 커맨드 표시), 언어 선택(ko/en).
- 백업: JSON 내보내기/가져오기(기존 transfer 재사용), 동기화 스위치, 히스토리(복원/삭제), 2단계 전체 초기화 커맨드.
- **전체 초기화 범위·순서 (R-3 — 설계상 파괴적)**: 초기화는 되돌릴 수 없는 파괴적 동작임을 인정한다. 저널·롤백으로 원자성을 흉내내지 않는다(v0.1.0 과설계) — 대신 각 단계를 **멱등·재시도 가능**하게 만들어, 중간에 실패해도 다시 눌러 끝까지 밀 수 있게 한다.
  - **지우는 대상**: 모든 프로필(→ 단일 default 프로필 하나), 선호값(테마·배지·언어·sync 플래그 → 기본값), **로컬 스냅샷**, **sync 스냅샷**, 세션 요약, 그리고 브라우저에 설치된 dNR 규칙(재컴파일로 비워짐).
  - **자동 백업 조율**: 런타임은 상태 변경 후 자동으로 백업을 예약한다 — 초기화가 이와 경쟁하면 방금 지운 데이터가 즉시 되살아난다. 그래서 초기화는 **자동 백업을 먼저 중단**하고 → 저장소(local+sync 백업 키)를 비우고 → 상태를 default로 리셋하고 → 자동 백업을 다시 켠다(그때 깨끗한 default가 스냅샷되는 것은 의도된 동작).
  - **멱등·재시도 (롤백 아님)**: 각 삭제 단계는 이미 비어 있어도 안전하게 다시 실행된다. 한 저장소 삭제가 실패하면 오류를 표면화하되 이미 완료된 삭제를 **되돌리지 않는다**(복구 불가능한 삭제를 롤백하는 척하지 않는다). 사용자는 초기화를 다시 눌러 남은 단계를 마치면 된다. "부분 실패가 부분 초기화를 막는다"는 지키지 못할 약속이라 뺀다.
  - **2단계 확인**: 파괴적이므로 확인(한 번 더 눌러 확인) 후에만 실행 — UI 가드.

### 셸·컴포넌트 (src/app, src/features, src/ui)

- 두 표면 단일 셸(ADR 0005) 위에 다크 리스타일. 레일은 아이콘+라벨. 프로필 열은 검색+색 스와치+인라인 토글+새 프로필. 본문은 아코디언 규칙 카드 + 인라인 RuleForm(수정 시 해당 규칙 맨 위 정렬).
- shadcn/Base UI/Tailwind/Motion 기존 스택으로 구현(새 라이브러리 없음, ADR 0015). 조합 래퍼(press-button, field-labeled, select-options 등, ADR 0014)를 재사용.
- 팝업 760×580 / 탭 전폭 분기는 기존 surface prop 그대로.

## Testing Decisions

좋은 테스트는 **외부 관측 가능한 행동**만 본다 — 컴파일된 dNR 규칙의 모양, 화면에 실제로 보이는 것, 저장·복원의 결과. 내부 구현(함수 이름, 상태 형태)에는 걸지 않는다. 새 시임은 만들지 않고 **기존 두 시임 + 레이아웃 진단**을 재사용한다(사용자와 합의).

- **core 단위 (vitest, `src/core/*.test.ts`)** — 순수 함수 시임. 여기서 검증:
  - 새 종류의 schema·model 생성/직렬화 (prior art: `schema.test.ts`).
  - **Compile 출력** — Block이 `action.type: 'block'`을, User-Agent가 `User-Agent` modifyHeaders를, Header Removal이 요청·응답 removeHeaders를 함께 내는지, 조건 조립이 기존과 동일한지 (prior art: `compile.test.ts`·`compile-headers.test.ts`가 `r.action`·`r.condition`을 직접 단언).
  - **Validation** — Block=URL만 필수, Header Removal=이름 필수·값 금지, User-Agent=값 필수 (prior art: `rule-validation.test.ts`).
  - **Block 넓은 스코프 판정 (R-4)** — 전역 와일드카드(`*://*/*`·`<all_urls>`)·도메인 앵커 없는 정규식은 '넓음'으로, 도메인 한정 패턴은 '좁음'으로 판정하는 순수 함수 표. 잘못된/미지원 패턴은 검증에서 거부.
  - **테마 해석 순수 함수** — `(pref, systemPrefersDark) → 'dark'|'light'` 표 (prior art: `i18n.test.ts`의 순수 매핑 테스트).
  - **배지 카운터 (R-5)** — `computeBadge`가 적용 규칙 수를 내는지: 적용 0→빈 텍스트, 일시정지→'II', N개→N, **부분 스킵(quota·컴파일 실패로 일부 규칙 탈락)에도 실제 적용 수**를 반영 (prior art: `badge.test.ts`).
  - **버전 호환성 + v1→v2 마이그레이션 (R-2, R2-2)** — **실제 v1 storage.local fixture**에서 stateStore가 로드될 때 v1→v2 마이그레이션이 모든 프로필·규칙을 보존하고 v2로 persist하는지(이 테스트를 v1 파일 import·백업 복원과 **별도로**), 마이그레이션 실패 시 default로 대체하지 않고 원본을 보존하는지, v2 왕복(모든 새 종류 포함), v3+ 미래 포맷을 만나면 데이터를 지우지 않고 보존, import의 미지 종류는 **오류로 거부** (prior art: `transfer.test.ts`·`schema.test.ts`·`persist` 로드 경로).
  - **백업 sync 스위치 (R-1, 단순 계약)** — 토글이 **앞으로의** 저장 대상만 바꾸고 **기존 스냅샷은 그대로 두는지**, UI 히스토리가 활성 저장소 것을 보여주고 다시 토글하면 반대쪽이 보이는지, 별도 "클라우드 백업 삭제"가 sync 저장소를 비우고 **삭제 실패 시 오류를 표면화**하는지 (prior art: `backup.test.ts`).
  - **전체 초기화 (R-3, 멱등)** — 로컬·sync 저장소가 채워진 상태에서 초기화가 열거된 키·상태를 모두 비우고, 자동 백업이 중단→재개되어 방금 지운 데이터가 되살아나지 않으며, **한 단계 실패 후 다시 실행(멱등)하면 끝까지 완료되는지**(롤백이 아니라 재시도) (prior art: `backup.test.ts`·`commands.test.ts`).
- **스모크 (Playwright, `scripts/smoke.mjs`)** — 실 확장 E2E 시임. 여기서 검증: 테마 스위치가 실제로 색을 바꾸고 다시 열어도 유지되는지, 새 종류 폼이 맞는 필드만 보이는지(Block=이름·값 없음, 삭제=이름만, UA=값만), 아코디언 편집이 규칙을 맨 위로 올리고 저장 시 접히는지, **넓은 스코프 Block 저장 시 경고·확인이 뜨는지(R-4)**, 백업 sync 토글, **2단계 전체 초기화가 확인 후에만 실행되는지(R-3)**, 빈 상태, 프로필 검색·인라인 토글. 기존 N-시리즈 단언 스타일을 따른다.
- **ui-diag (`scripts/ui-diag.mjs`)** — 레이아웃·성능 회귀. 탭 앱 와이드 레이아웃이 가로로 넘치지 않고, 팝업이 760×580을 유지하며 시작 지표가 회귀하지 않는지. 다크/라이트 양 테마 스크린샷.

## Out of Scope

- **디버그/로그 실시간 패널** — onRuleMatchedDebug(declarativeNetRequestFeedback)는 개발자 모드 전용이라 배포판 무동작. 설정에서 토글 자체를 뺀다.
- **일본어(ja)** — 번역이 없어 선택지에서 제외. ko/en만.
- **새 키보드 커맨드** — 단축키 패널은 현재 커맨드 표시만. Alt+Shift+N 등 신규 바인딩은 추가하지 않는다.
- **새 UI 라이브러리** — Dice/Coss/Magic/Cult/Aceternity 도입 없음(ADR 0015).
- **팝업 크기 확대** — 팝업은 760×580 유지(ADR 0005). 1100×700은 탭 앱 참조.
- **Block의 무거운 안전장치 (R-4 이월)** — 보호 URL 허용목록(특정 도메인은 차단 금지), 차단으로 깨진 페이지의 자동 복구는 이번 범위 밖. 이번엔 넓은 스코프 경고·확인 + 실효 스코프 상시 표시 + 전역 Pause 탈출구까지만.
- **구버전 롤백 소급 보장 (R-2 이월)** — 이미 배포된 구버전으로의 다운그레이드 안전은 그 구버전 코드가 정하므로 소급 불가. v2 계약은 전방(v2 이후) 안전만 정의.
- **저장소 간 히스토리 자동 이관 (R2-1·R2-4 단순화로 이월)** — sync↔local 토글이 기존 스냅샷을 원자적으로 옮기는 트랜잭션(복사·검증·직렬 writer·자동백업 드레인)은 v0.1.0에 과설계라 넣지 않는다. 토글은 앞으로의 위치만 정하고, 클라우드 삭제는 별도 명시 동작.
- **초기화 트랜잭션 롤백 (R2-3 단순화로 이월)** — 파괴적 삭제를 되돌리는 저널·롤백은 넣지 않는다. 초기화는 설계상 파괴적이며 멱등·재시도로만 다룬다.

## Further Notes

- **Block 안전성**: 요청 차단은 스코프가 넓으면 페이지를 깨뜨릴 수 있는 유일한 파괴적 종류다. 릴리스 게이트(Stage 5)에서 과도 차단·차단 범위 표시를 검토한다. 권한은 기존 `declarativeNetRequest`로 충분(block 액션 포함).
- **테마·백업 개정**: ADR 0004(테마 스위치 없음)와 "백업은 항상 sync"를 개정한다 — 근거·경계는 ADR 0015.
- **폰트 게이트**: Geist 번들은 별도 에셋이라 JS 번들 게이트 밖이지만, ui-diag 시작 지표로 첫 페인트 회귀를 지킨다.
- **라이트 팔레트**: 디자인은 다크만 그렸다. 라이트는 디자인 다크를 기준으로 파생하며, 두 테마 모두 대비 기준(본문 4.5:1, 비텍스트 3:1)을 지킨다.
