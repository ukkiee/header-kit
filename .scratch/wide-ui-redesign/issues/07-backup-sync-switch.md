# 07 — 백업 sync 스위치 + 클라우드 삭제

**What to build:** 백업 저장 위치를 sync(기기 간 동기화)와 local(이 브라우저만) 중 고르는 스위치. 단순 계약 — 토글은 **앞으로의** 백업 위치만 정하고 기존 스냅샷을 이관하지 않는다. 클라우드 잔재를 지우려면 별도의 명시적 "클라우드 백업 삭제" 동작을 쓴다(삭제 검증). 이 단순화가 원자적 이관·동시성 경쟁 문제를 구조에서 없앤다.

**Blocked by:** 01 (백업 화면 셸).

**Status:** ready-for-agent

- [ ] sync 저장 여부 플래그를 더하고, backup.ts의 **앞으로의** 저장 대상이 이 플래그에 따라 storage.sync ↔ storage.local로 갈린다(매니페스트·복원·quota는 대상에 맞춤)
- [ ] 기존 설치 기본값은 sync ON (기존 히스토리가 그대로 보임)
- [ ] 토글이 기존 스냅샷을 이관하지 않는다 — UI 히스토리는 활성(현재 선택) 저장소 것을 보이고, 다시 토글하면 반대쪽이 다시 보인다(어느 것도 삭제·이동 안 됨)
- [ ] 별도 "클라우드 백업 삭제" 버튼(자체 확인 + **삭제 검증**, 실패 시 오류 표면화) — sync OFF와 클라우드 삭제가 분리되어 "이 브라우저에만"이라는 거짓 표시가 없다
- [ ] 사용자 대면 라벨 '클라우드 동기화', 상태 문구는 켜짐/꺼짐 + 클라우드 잔존 여부
- [ ] core 테스트: 토글이 앞으로의 대상만 바꾸고 기존 스냅샷 보존, 활성 저장소 히스토리, 클라우드 삭제 검증·실패 표면화 (prior art: backup.test.ts)
- [ ] 전 게이트 그린. (저장소 간 자동 이관 트랜잭션은 범위 밖.)
