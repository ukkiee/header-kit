## 이 슬러그가 닫은 것

게이트가 일곱에서 **열여섯**으로 늘었고, 그중 아홉이 이번에 생겼다. 각 티켓은 관계를 깨뜨리는
픽스처로 자기 게이트가 **실제로 거절하는지**를 확인했다 — 설정이 있다는 것과 설정이 동작한다는
것을 구분하는 것이 이 기능의 방법론이다.

| 티켓 | 무엇이 서고, 무엇으로 그것을 증명했나 |
|---|---|
| 01 | 게이트 레지스트리·표·러너. 판정 넷(PASS/FAIL/N/A/BLOCKED)이 실재하고 네 자리 일치가 검사된다 |
| 02 | 회차별 산출물 디렉터리. **낡은 산출물이 통과를 만들지 못하는 것**을 소스 변경 + 빌드 차단으로 재현 |
| 03 | `manifest-gate`. 권한 증감·미달 버전·CSP 토큰을 실제 빌드 없이 뒤집는 픽스처 31 |
| 04 | 레이어 방향. 42쌍 트리에서 상향 21쌍이 전부 보고되고 하향은 하나도 보고되지 않는 것 |
| 05 | 포매터 + **재현 증명**. 부모 트리에 고정 버전 `oxfmt`를 돌린 결과가 포맷 커밋의 트리와 같음 |
| 06 | 접근성 **지문** 베이스라인. 하나가 사라지고 다른 하나가 생겨 총계가 같은 경우가 FAIL |
| 07 | 오버플로는 하드 게이트, 성능 대조는 자문 행. 준비 표지가 서지 않으면 **훑지 않고 FAIL** |

## 검증이 덮지 못하는 것 — 알고 남긴 한계

**실제 GitHub Actions 실행은 아직 관측되지 않았다.** CI 경로는 **리눅스 컨테이너**(node:24 ·
bun 1.3.11)에서 `bun install --frozen-lockfile && bun run gate:ci`로 12행 전부 PASS를 확인했다.
그러나 그것은 `ubuntu-latest` 러너가 아니다. 첫 실제 실행이 이 브랜치의 첫 PR에서 난다.

그 컨테이너 실측이 **CI 빨강 둘을 미리 잡았다**(둘 다 이 슬러그 안에서 고쳤다):

1. `scripts/oxlint-config.test.mjs`가 oxlint의 **사람이 읽는 형식**을 정규식으로 긁고 있었는데
   그 형식이 환경에 따라 다르다(macOS 한 줄 / 리눅스 그래픽). 컨테이너에서 진단이 **0건으로 접혀**
   케이스 열 개가 빨강이었다. 반대 방향이 더 나빴다 — "진단이 없어야 한다"는 케이스는 형식이
   바뀌면 **영원히 초록**이라 규칙이 꺼져도 알 수 없다. `-f json`으로 못박고 파싱 실패를 던지게 했다.
2. `service-worker.integration.test.ts`의 펜스 테스트 둘. vitest 기본 예산(5초)이 `FENCE_WAIT_MS`와
   **정확히 같아 여유가 0**이었다. 시간 초과가 다음 테스트의 탐색을 오염시켜 전혀 다른 사유로 번졌다.

그 밖의 한계는 `docs/agents/verification.md`의 "이 검사가 덮지 못하는 것"과 `README.md`의
"각 게이트가 보장하지 않는 것"·"알려진 빈틈"이 갖는다. 여기 옮겨 적지 않는다 — 두 자리에 적으면
갈라선다. 요약하면: 게이트 스크립트의 테스트 커버리지가 고르지 않고(`smoke-barriers`·`ui-perf`·
`smoke`의 로직에는 테스트가 없다), 자리 일치 검사가 `needs` 칸을 대조하지 않으며,
`core-line-budget`은 상한이지 하한이 아니고, README 파리티는 산문의 **사실 여부**를 재지 않는다.

## 이 증거의 성질

**게이트 열여섯 행이 초록이라는 것은 이 저장소가 옳다는 뜻이 아니다.** 각 행이 재기로 선언한 것을
재고 만족했다는 뜻이다. 무엇을 재기로 했는지는 `docs/agents/verification.md`가, 무엇을 재지 않기로
했는지는 그 문서와 `README.md`가 갖는다.

**이 기능의 산출물은 대부분 검사 자신이다.** 그래서 "게이트가 통과했다"보다 "게이트가 실패해야 할 때
실패한다"가 더 중요한 증거이고, 위 표의 오른쪽 칸이 그것을 적는다. 통과 케이스만 있는 게이트는
vacuous pass를 잡지 못한다 — 이 저장소는 그 실패를 이미 한 번 겪었다.
