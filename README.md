# HeaderKit

프로필 기반으로 HTTP 요청/응답을 수정하는 Chromium 확장 프로그램. 켜진 동안 정해진 범위 안에서만
트래픽을 변조하고, 끄면 흔적을 남기지 않는다. 헤더 추가·변경·삭제, 요청/응답 쿠키, 리다이렉트,
User-Agent 변경, 요청 차단을 **Profile** 단위로 묶어 켜고 끈다.

MIT 라이선스. `package.json`이 `private`로 표시된 개인 프로젝트다.

## 이 문서가 하려는 일

검사가 **무엇을 보장하고 무엇은 보장하지 않는지**를 같은 자리에 적는다. 보장하는 것만 적으면
읽는 사람은 나머지도 보장된다고 읽고, 그러면 초록이 실제보다 넓은 것을 뜻하게 된다. 아래
`각 게이트가 보장하지 않는 것`이 이 문서에서 가장 중요한 절이다.

## 시작하기

```sh
bun install       # 의존성. 락파일은 `bun.lock`
bun run check     # 설치 직후에 바로 돌린다 (아래 참고)
bun run dev       # 개발 빌드 + 감시
bun run build     # 프로덕션 빌드 → .output/chrome-mv3
```

패키지 매니저는 **bun**이다. npm·yarn·pnpm을 쓰지 않는다. 설치 직후에 `bun run check`를 돌리는
것은 관습이 아니라 흉터다 — `node_modules`가 깨진 채 다음 걸음을 딛는 사고가 두 번 났고, 두 번 다
설치 시점이 아니라 한참 뒤에 다른 얼굴로 나타났다.

## 검증

```sh
bun run gate               # 등록된 게이트를 전부 돌린다
bun run gate:ci            # CI가 도는 것과 정확히 같은 부분집합 (브라우저 불필요)
bun run gate --check-only  # 자리들이 어긋나지 않았는지만 본다 (게이트를 돌리지 않는다)
```

개별 게이트는 그 행의 명령을 직접 부르면 된다 — 명령의 정본은 게이트 표다. 표는
`docs/agents/verification.md`가 소유하고, 기계가 읽는 같은 목록은 `scripts/gates.txt`다.
**둘이 갈라서면 러너가 FAIL을 낸다.**

**판정은 넷이다.** `PASS`(돌았고 만족했다) · `FAIL`(돌았고 만족하지 못했다) · `N/A`(잴 대상이
없다) · `BLOCKED`(선행이 통과하지 못해 판정 자체를 얻지 못했다). **돌리지 않은 검사를 `PASS`로
적지 않는다.**

**브라우저가 필요한 것과 아닌 것.** `bun run gate:ci`가 도는 집합에는 실제 크롬을 띄우는 게이트가
하나도 없다. 크롬이 필요한 행은 로컬에서만 돈다 — 어느 것인지 여기 세어 두지 않는다. 레지스트리의
`browser` 칸이 정하고, 테스트 파일의 분류(`*.browser.test.mjs`)도 거기서 파생된다.

**자문 행(advisory).** 행의 `kind`가 `advisory`면 관측을 남기되 **완료를 가로막지 않는다.** 기기에
매인 측정처럼, 하드로 걸면 거짓 실패를 내고 그 거짓 실패를 고치는 유일한 길이 임계값 완화가 되는
자리에 쓴다. 판정 토큰은 그대로 `FAIL`이다 — 완료를 막지 않는 것은 판정이 아니라 그 행의 `kind`이고,
다섯 번째 판정은 만들지 않는다. 어느 행이 그런지와 근거는 표가 갖는다.

## 각 게이트가 보장하지 않는 것

**경계를 먼저 긋는다.** 각 행이 무엇을 재는가(임계값)와 각 한계의 **근거**는
`docs/agents/verification.md`가 갖는다. 여기 적는 것은 처음 온 사람이 초록을 어디까지 믿어도 되는지
**한 줄로** 아는 것이고, 왜 그런지가 궁금하면 그 문서로 간다. 두 자리가 갈라서지 않게 하는 것은
id 집합뿐이다 — 산문은 검사하지 않으므로, 근거를 고칠 때는 그 문서를 고치고 여기는 요약으로 둔다.

| 게이트 | 보장하지 **않는** 것 |
| --- | --- |
| `check` | 타입이 맞는다는 것이지 동작이 옳다는 것이 아니다. `scripts/`는 타입 프로그램 밖이라 그곳의 타입 오류는 이 게이트에 잡히지 않는다 |
| `lint` | 켜는 것은 correctness 카테고리다 — style·pedantic·restriction은 재지 않는다. 무엇을 잡는지(레이어 방향·순환·떠도는 프로미스를 포함한다)는 표의 임계값 칸이 갖는다 |
| `format` | 포맷이 같다는 것이지 코드가 옳다는 것이 아니다. 마크다운과 기록물(`docs/reviews/`·`.scratch/`)은 대상이 아니다 |
| `core-line-budget` | **상한이지 하한이 아니다** — 코어를 비우면 통과한다. 줄 수만 재고 내용이 코어에 살 자격이 있는지는 재지 않으며, 코어가 실제로 로드됐는지도 재지 않는다 |
| `a11y-gate` | **"새 지문이 없다"까지만**이다(개수가 아니라 지문의 집합을 잰다). 키보드로 전체 흐름을 조작할 수 있다거나 모든 컨트롤에 접근명이 있다는 **관측된 보장은 주지 않는다.** 기존 위반은 베이스라인이 안고 있고, 고친 위반의 지문을 지우지 않으면 **같은 위반이 다시 들어와도 통과한다.** `--update`는 좁히기도 넓히기도 한다. **같은 파일·같은 규칙 안의 교체는 구분하지 못한다** — 하나를 지우고 하나를 만들면 통과한다 |
| `test` | 스위트가 단언하는 것만. 게이트 스크립트 커버리지는 고르지 않다(아래 `알려진 빈틈`) |
| `build` | 빌드가 성공한다는 것이지 산출물이 옳게 동작한다는 것이 아니다 |
| `storybook` | 스토리북이 빌드된다는 것이지 스토리가 옳게 보인다는 것이 아니다 |
| `smoke-barriers` | 준비 배리어가 **있다**는 것이지 그 배리어가 옳은 것을 기다린다는 것이 아니다. 이 스크립트 자신에는 테스트가 없다 |
| `bundle-gate` | 지금 수치가 한도 안이라는 것. 한도를 넘는 픽스처가 FAIL을 내는 것은 확인되지만, **그 한도가 옳은 값인지**는 재지 않는다 — 숫자의 근거는 스크립트 주석의 이력이다 |
| `writer-lane-gate` | 레인 생성 자리와 표지 수를 센다는 것이지 레인 규율이 코드 전체에서 지켜진다는 것이 아니다. 표지는 **문자열이 있는지**만 보므로, 레인을 쓰지 않고 표지 문자열만 담은 파일도 누출로 읽힌다 |
| `manifest-gate` | **"표면이 선언과 같다"를 증명하지 "이 표면이 이 확장에 옳다"를 증명하지 않는다.** 후자는 `smoke`가 잰다. `unsafe-eval`은 프로덕션 CSP(`extension_pages`)에서만 재고 `sandbox`의 **값**은 재지 않는다 |
| `overflow-gate` | 최대 길이 이름을 심은 그 시드·그 폭에서 넘침이 없다는 것. 다른 시드와 다른 창 크기는 재지 않는다 |
| `test-browser` | 브라우저를 띄우는 픽스처가 통과한다는 것. **CI에서는 돌지 않는다** |
| `ui-perf` | **자문 행이다.** 기준선을 측정한 기기 밖에서 나오는 빨강은 코드가 아니라 기기를 말한다. 이 계측이 옳은지 재는 테스트가 없다 |
| `smoke` | 시나리오에 적힌 것만. 시나리오에 없는 흐름은 재지 않으며 이 스크립트의 시나리오 로직에는 테스트가 없다 |

<!-- gate-limits:end -->

이 표가 다루는 게이트 집합이 레지스트리와 어긋나거나 **한계 칸이 비면**
`scripts/readme-parity.test.mjs`가 FAIL을 낸다 — 게이트가 하나 늘었는데 그 한계가 아무 데도 적히지
않는 상태를 막는다. 그 검사 자신도 관계를 하나씩 깨뜨리는 픽스처로 물린다.

## 하네스 코어

에이전트가 모든 태스크에서 항상 받아야 하는 지시 묶음은 `AGENTS.md`의 `core:begin`/`core:end`
마커 **사이에 인라인으로** 산다. `CLAUDE.md`는 `@AGENTS.md` 한 줄이다.

별도 파일에 두고 import하지 않는 이유는, 그 형태가 **"import가 실제로 로드되었는가"를 증명
대상으로 만들기** 때문이다 — 인라인된 코어로 답한 세션과 파일을 조용히 읽어 답한 세션은 답만 봐서는
구별되지 않고, 그 부정을 증명하는 비용에는 바닥이 없다. 인라인은 그 질문에 답하는 대신 질문을
없앤다. 부수 효과로 `AGENTS.md`를 읽는 다른 도구도 같은 것을 받는다. 근거의 정본은 `docs/adr/`의
ADR 0018이다.

코어의 크기는 코어가 스스로 선언한 라인 예산을 `core-line-budget` 게이트가 재는 것으로 지킨다.
항상 로드되는 문서는 커지면 커진 만큼 매 태스크에 비용이 붙는데, **커졌다는 사실이 아무 데도
나타나지 않기** 때문이다.

## 알려진 빈틈

초록이 덮지 못하는 자리다. 전부 의도적으로 열려 있고, 닫는 길이 있으면 그 자리에 적혀 있다.

- **게이트 스크립트의 테스트 커버리지가 고르지 않다.** `bundle-gate`는 **계측 임계값의 회귀도
  픽스처가 문다**(한도를 넘는 산출물 트리·지연 계약 청크가 즉시 집합에 든 트리). `writer-lane-gate`는
  이제 **`fail()`로 판정하는 실패 경로 전부**가 뒤집힌다 — 변조 스윕으로 확인했고, 무엇을 어떻게
  변조했는지는 `docs/agents/verification.md`가 갖는다. ~~소스 쪽 검사 둘은 픽스처로 뒤집을 수
  없다~~ **그 진단이 틀렸다**: 그 검사들을 조종하는 것은 `--artifacts`가 아니라 cwd이고 대상 인자
  없이 뒤집힌다. `smoke-barriers`·`ui-perf`·`smoke`의 로직에는 여전히 테스트가 없다.
- **`writer-lane-gate`는 깨진 매니페스트에서 판정 토큰 없이 죽는다.** 산출물의 `manifest.json`이
  존재하지만 파싱되지 않으면 스택 트레이스만 남는다. 러너가 "상태 줄 없음"으로 FAIL을 내므로
  거짓 초록은 아니지만 사유가 운영자에게 가지 않는다 — 형제인 `manifest-gate`는 같은 입력을
  판정으로 바꾼다.
- **`scripts/`는 `tsconfig.json`의 타입 프로그램 밖이다.** 그곳의 타입 오류는 `check`에 잡히지
  않는다. `lint`의 type-aware 판정은 자기 타입 프로그램을 세워 `scripts/`도 재지만, `.mjs`에는 타입
  선언이 없어 추론이 `any`로 떨어지는 자리가 있다.
- **접근성 기존 위반이 베이스라인으로 남아 있다.** `a11y-gate`는 새 진단이 늘지 않는 것만 지킨다.
  줄어드는 것은 막지 않지만 자동으로 줄지도 않는다.
- **접근성 지문은 같은 파일·같은 규칙 안의 교체를 구분하지 못한다.** 하나를 지우고 하나를 만들면
  개수까지 같아 통과한다. 소유 요소를 지문에 넣어 좁히려는 시도를 네 번 했고 네 번 다 거짓 초록이나
  거짓 빨강을 만들어 되돌렸다 — 근거는 `docs/agents/verification.md`가 적는다.
- **CI를 통째로 없애는 것은 막지 못한다.** 레지스트리·표·워크플로를 셋 다 되돌리면 자리 일치는
  초록이다. 다만 그 뒤로 CI는 초록을 내는 것이 아니라 아예 돌지 않는다.
- ~~실제 GitHub Actions 실행은 아직 관측되지 않았다.~~ **관측됐다** — 첫 PR에서 `pull_request`
  트리거가 걸려 `gate:ci` 12행이 전부 통과했다(`ubuntu-latest` · bun 1.3.11 · node 24).
